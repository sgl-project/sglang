Experimental Ascend LIM sparse KV offload
========================================

Purpose and configuration
-------------------------
Integrate the external FusedLightningIndexerManage (LIM) operator into the
SGLang DSA NPU decode path. Full compact attention KV remains in registered
host DRAM; each request/layer retains C tokens of main KV in HBM. Full indexer
keys remain in HBM. K is the selected TopK count, fixed at 2048; C is the
resident capacity and does not increase TopK.

The default remains legacy. Experimental modes are explicit:
  SGLANG_NPU_ENABLE_SPARSE_KV_OFFLOAD=1
  SGLANG_NPU_SPARSE_KV_INDEXER=li_reference|lim
  SGLANG_NPU_SPARSE_KV_CACHE_SIZE=4096
  SGLANG_NPU_LIM_LIBRARY=/absolute/path/to/native/operator.so

Alternatively set CACHE_SIZE=0 and SGLANG_NPU_SPARSE_KV_HBM_BUDGET_MB to derive C.
This per-rank manager budget covers persistent resident KV, slot maps, policy
and selected/adapter workspaces. Model weights, full indexer KV, allocator
fragmentation, graph pools and kernel temporaries require separate headroom.
The native dummy key-scale workspace is reserved separately in pool sizing.

Current adapter limits: BF16 indexer/main KV, Q1, K=2048, page=128, PP=1,
DCP disabled, speculative decoding disabled; C is a multiple of 128 in
[2048,32640], and source capacity is at most 2**21. C8 is unsupported here.
The native operator must already be installed; this change does not build it.

Selection semantics and accuracy status
--------------------------------------
For an offloaded request (page-aligned prefix >= C), select K from the stable
prefix and attend all currently visible tail tokens as well. The Q1 adapter
has at most one visible 128-token tail page. Short requests use the non-offload
route. IndexShare consumers reuse the anchor plan with their own layer KV.

This differs from the original full-sequence TopK policy. Equal results against
the same-policy LI reference do not establish model-quality parity against
full-sequence TopK. C controls resident capacity rather than K. Once both
configurations are in the offload route, misses are fetched rather than
dropped. The experimental route threshold is page-aligned prefix >= C:
changing C can therefore change the selection policy near that threshold.
Cross-C quality equivalence is not claimed for these transition lengths.
Incorrect cache routing would still be a correctness bug, hence the bitwise
KV checks.

Covered on real NPU: TopK set parity on fixed fixtures with wide score margins,
bitwise selected KV parity, SFA output tolerance rtol=0.01/atol=0.002, cold fill,
short requests, request allocation/reset/reuse, indexer entry, new-token D2H,
IndexShare payloads, graph capture/replay, and post-timing payload checks.
Dynamic graph coverage crosses seq_len 8193 -> 8321, forces the newly visible
page into TopK, then exercises mixed padding and request reuse. Invalid source
IDs are masked explicitly because the native invalid-row path can retain stale
outputs during graph replay.

The 151 results below are fixed-input subpath measurements. Full checkpoint
generation and serving on 217 are documented separately below; they must not
be inferred from the 151 timings. The earlier checkpoint size estimate was not
a measured model run. The actual 217 checkpoint metadata reports
404,689,509,888 weight bytes. The fixed 151 dimensions were index H=32/D=128,
K=2048, CKV=512, KPE=64, local attention QH=8.

Still outside validation: full-distribution KL, perplexity, broad task-quality
parity, speculative decoding, C8, and the SHMEM runtime. Equal fixed-fixture
KV payloads do not establish general end-to-end numerical equivalence.

do not attribute the measured difference to Python interpreter time alone.

Full GLM-5.2-W4A8 validation on 217, 2026-10-20
---------------------------------------------
Environment: 16 Ascend A3 chips, 64 GiB HBM each; Python 3.12.13,
torch 2.10.0+cpu, torch_npu 2.10.0.post6, CANN 9.1. The complete local
GlmMoeDsaForCausalLM checkpoint was loaded. Its metadata weight size is
404,689,509,888 bytes. W4A8 applies to model weights/activations; this
experiment explicitly uses BF16 indexer/main KV, not C8.

Source provenance: original integration bc75a6195e073aa8754e534a8a1492df5d802315
on official main 4b83f215f498bc0371587bfae4a9470f24e77737. Tuned implementation
d9786495c0dadc86558b58e14d788bc0a61f38e1 changes only the native resident-KV
gather launch from 24 to 48 blocks; it also adds the two portable model clients.
The native operator library is unchanged and retains the SHA256 listed above.

All model modes use TP16/EP16, DeepEP auto, shared-expert fusion disabled,
BF16 dtype/KV, context length 36864, max running requests 16, max total tokens

The production create_shm_tensor allocator and real registered host DRAM were

Serving measurements include weights, projections, TP/EP communication,
per-layer new-token writes to DRAM, real miss reads, selection/cache work,
attention, sampling, and scheduling. Inputs are prepared once as token IDs
and reused. Each workload has one excluded warmup round and three measured
rounds; report medians, without outlier removal. TTFT includes prefill; TPOT
is the streamed interval between the first and last completion divided by
the completion-count difference. Throughput includes request prefill time.
Profiles are collected in a separate request after timing and quality finish.
