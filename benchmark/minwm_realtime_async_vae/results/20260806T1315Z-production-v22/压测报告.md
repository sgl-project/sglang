# MinWM Realtime 生产链路压测报告

## 1. 结论

本轮正式压测已经完成。最终部署在 8 x H100 Spot Denoiser、1 x L4 Spot TAEHV VAE、
2 x Gateway、2 x Coordinator 上，完整经过公网 NLB。生产低延迟准入设为每张 H100
1 个 Session，因此当前最高稳定并发和硬准入上限均为 8。

在 1/2/4/8 并发各 3 轮的正式测试中，所有 Session 成功，错误率为 0。8 并发的
Action 到首批画面 P95 为 865.15 ms，最慢会话 34.00 FPS，满足小于 1 秒和不低于
16 FPS 的验收门槛。12 并发边界测试中 8 个成功、4 个明确返回
`CAPACITY_EXHAUSTED`，证明系统不会在容量满时无界积压。

## 3. 测试方法

- 完整链路：`Browser/LoadGen -> NLB -> Gateway -> Coordinator -> H100 Denoiser -> L4 VAE -> Gateway -> Client`。
- 正式容量测试：并发 1/2/4/8，每档 2 个 warmup Chunk、6 个计量 Chunk，连续运行 3 轮。
- 每轮开启完整 HTTP Trace，统计 Chunk、Action、Denoise、VAE Decode、Frame Encode、
  Queue、Credit Wait 和 Pipeline Overlap。
- 边界测试：12 个长连接同时进入，验证容量满时的拒绝语义。
- 功能测试：真实 Chrome 完成 T2V、I2V、Action、Prompt Update、Trace UI、Recording 和 Dump 回放。
- 故障测试：活动 Denoiser Pod Kill、断连重连和慢消费者。

## 5. 异步 VAE Overlap

| 并发 | Overlap Mean | Overlap P95 | 串行等价值 | 隐藏的串行时间占比 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 202.006 ms | 206.947 ms | 795.030 ms | 25.4% |
| 2 | 204.567 ms | 220.998 ms | 804.252 ms | 25.4% |
| 4 | 229.820 ms | 260.060 ms | 854.972 ms | 26.9% |
| 8 | 303.932 ms | 327.987 ms | 1065.493 ms | 28.5% |

“串行等价值”按 `观测 Chunk 关键路径 + 已重叠阶段` 计算。它表明异步流水实际隐藏了
约 202 到 304 ms，且并发越高 overlap 越明显。不过本轮没有在完全相同代码 revision、
Trace 和准入配置下关闭异步 VAE，因此这个比例是 Trace 观测的并行收益估算，不能冒充
严格的同步/异步 A/B 加速比。

## 6. 调度修复收益

压测最初发现 Coordinator 会把多个 Session 堆到少量 H100，导致其余 GPU 空闲。修复后
候选排序使用稳定 Worker/slot 层级，并把低延迟生产准入限制为每卡 1 Session。

| 并发 | 指标 | 修复前 | 修复后 | 变化 |
| ---: | --- | ---: | ---: | ---: |
| 4 | 聚合 FPS | 38.608 | 156.170 | 4.05x |
| 4 | 最慢会话 FPS | 10.854 | 40.811 | 3.76x |
| 4 | Chunk P95 | 1718.814 ms | 651.822 ms | -62.1% |
| 4 | Action 首帧 P95 | 1049.583 ms | 726.761 ms | -30.8% |
| 8 | 聚合 FPS | 74.160 | 246.161 | 3.32x |
| 8 | 最慢会话 FPS | 10.728 | 34.002 | 3.17x |
| 8 | Chunk P95 | 1748.659 ms | 795.259 ms | -54.5% |
| 8 | Action 首帧 P95 | 1078.708 ms | 865.149 ms | -19.8% |

这也是为什么不能把 Worker 的内部 `max_sessions=4` 直接当成生产容量。对于当前模型和
16 FPS 低延迟 SLO，实测安全值是每 H100 1 个 Session。

## 7. 容量边界

12 并发长连接测试结果：

| 请求数 | 成功 | 容量拒绝 | 成功会话聚合 FPS | 最慢成功会话 FPS | Chunk P95 | Action P95 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 12 | 8 | 4 | 256.56 | 32.88 | 560.99 ms | 918.97 ms |

4 个失败均为明确的 `CAPACITY_EXHAUSTED`。因此当前配置的最高稳定并发是 8，硬准入也是
8。横向增加 H100 Worker 后 Coordinator 会增加 Denoiser slot；VAE Pool 需要根据
Decode/Credit 指标同步扩容，不能只增加 Denoiser。

## 8. 浏览器、Trace 与 Dump

- Chrome 公网探针：Display Lag P50 `26.1 ms`、P95 `69.93 ms`，持续播放 Render 约 `24 FPS`。
- T2V：Socket 保持 Live，连续渲染 177 帧；Action 到画面链路通过。
- I2V：Reference 为 `preset_url`，JPEG `154078 bytes`，生成和播放通过。
- Recording：录制 `945` 帧，WebM `609905 bytes`，自动产出 WebM、JSON、HTML。
- 在线轨迹：共 `660` 个事件，包含 key down/up、实际 camera action、2 次 Prompt Update、
  Chunk、Trace 和录制生命周期。
- Trace：HTTP 页面读取 220 个事件；样本 Chunk #57 总耗时 610 ms，Scheduler
  P50/P95 为 394/451 ms，Denoise 为 387/431 ms，VAE Decode 为 35/38 ms。
- Trace 不再占用视频 WebSocket；CloudWatch 保留 5 天，UI 打开 Trace 页面时按需查询。

## 9. 故障测试

### 9.1 活动 Denoiser Kill

在并发 Session 运行时删除活动 Denoiser Pod，绑定该 Worker 的 Session 返回
`WORKER_LOST`，其他 Worker 上的 Session 继续运行。Kubernetes 约 69 秒后拉起新 UID，
恢复后重新执行 8 并发，8/8 成功。

### 9.2 断连、重连与慢消费者

- 客户端断开后，同用户立即重连可能短暂收到 `USER_SESSION_LIMIT`；经过 3 次退避，
  `2373.765 ms` 后成功。调用方必须对这类可重试错误做带抖动退避。
- 慢消费者暂停读取 8 秒后仍完成 12 个 Chunk；有界 Buffer/Credit 没有无限增长。
- 真实 AWS Spot interruption notice 和 Kubernetes Drain 云事件尚未注入。Worker Kill、
  preStop/Drain 代码和单元测试已覆盖核心语义，但正式放量前仍应补跑云级 Chaos Gate。
