# Session KV 生命周期实现与压力验收

2026-11-05。基于保留上游合入历史的 `rfc-kvc`，本轮五个独立配对测试通过预注册验收：有效工作吞吐 **+31.58%**，计入源发布分摊后的完整作业吞吐 **+22.52%**，全部完成请求的合并 p95 TTFT **−26.42%**。每种策略完成 8,960 次恢复，输出与控制收尾全部有效。结果适用于本文的 FULL/TP1、Mooncake TCP、固定生命周期负载。

实现集中处理控制请求的串行等待、被排队耗时延长的恢复窗口、到期准备任务的推进机会，以及读取容量和真实 demand 的竞争。PIN、PREFETCH、DEMOTE 保持独立契约；策略可跳过无收益操作。新策略默认关闭，每项功能经审阅和测试后单独提交。没有修改模型权重或普通推理的输出语义。

## 配置与计量

两台独立 TP1 FULL Engine，Qwen3-8B BF16。源 A 为 A100 80GB PCIe，固定目标 B 为 A100-SXM4-80GB；配对组始终使用同一个 B。两侧 `mem-fraction-static=0.8`，无人工 `max-total-tokens` 上限。B 的实际 L1/L2 容量为 346,944/693,952 tokens；每轮 64×16K 前缀共 1,048,576 tokens，约为 L2 的 **1.51 倍**。

HiCache ratio=2、write_through、direct/page_first_direct，Mooncake 0.3.14 TCP，每 Engine `global_segment_size=128GB`，使用本任务独占 Master。overlap 关闭，prefill/decode CUDA graph backend 均显式设为 disabled，统一开启 deterministic inference。旧 `disable_cuda_graph` 字段仍为 false；实际 backend 参数和运行日志见外部证据 `proofs/effective-graph-proof.json.gz`。不能只凭旧字段判断是否使用 graph。

目标上下文上限 32768，page=64，chunked prefill=4096，C32，输出固定 32 tokens。读取预算为在途 131,072 tokens、推测读取 65,536 tokens、demand 余量 32,768 tokens；最多四个 native read，真实 demand 优先。Router poll=250ms、成本分位 p90、最大提前量 10s、自动短 PIN TTL=0、最小冷层驻留 3s。Engine 实际执行容量审批，Router 观测用于筛选。

五个预声明种子为 200001、210001、220001、230001、240001。每轮 64 个独立前缀、28 次复用，每种策略 1792 次恢复；共 320 个不同前缀、每种策略 8960 次恢复。实际前缀哈希与筛选/补测集及其他独立轮次不相交，每轮使用新 salt/run ID、新 Router 和空成本模型；每组重置目标缓存。两组顺序由种子随机决定。冻结配置后未根据正式结果调参或提前停止。

主场景工具等待 3s。有效工作时间包括任务注册、工具等待、控制背压、生成及异步操作排空，排除实验缓存重置。源前缀每轮实际发布一次，共执行 128 次源生成；公共发布时间等分进入该轮两个组的完整作业口径，即 `complete_job_wall_s = work_wall_s + source_execution_wall_s / 2`。输入材料构造和离线分析不属于该口径。

受控恢复请求直接进入 B，生命周期控制经过 Router。此结果没有验证自由路由/indexer 的整体吞吐，也未接入真实 trainer；训练等待时间保留为 unknown。closed-loop 客户端的发送迟到完整保留。

GET payload 减少 **22.44%**。该值统计实际后端 API 请求覆盖的 KV 数据量，保留重复和失败调用成本；没有测得网络 wire bytes，不能解释为线速或总 GET+PUT 网络流量。L3 在两组中均没有缺失，本轮无法证明 L3 PIN 在后端容量竞争下的保留收益。

host byte-seconds 减少约 24.51%，主要随完成时间缩短；平均驻留量仅小幅变化，不能据此声称 L2 容量需求减少 24.51%。积分包括 staging 和引用占用，边界、缺口与多池不外推。loaded tokens 和操作范围按操作累计，均不等于同时物理去重驻留量。

Router 平均观测 CPU 从约 0.051 核增至 0.098 核，存在控制成本；目标 B 的每任务观测 CPU 降低。Engine/Router 采样覆盖至少 99.56%，只报告实际观测区间，不推算边界。驱动客户端 CPU 未单独归因；资源采样器短命子进程的部分区间未知，不将已观测 CPU 解释成机器总 CPU。采样器自身和主机压力原始记录均保留。

只有 626 次恢复在发请求前确认就绪，因此全部收益不能归因于提前完成 I/O。在途复用与减少重复 prefill 同时贡献收益。普通按需路径仍可能在读取发布后、GPU 准入前丢失 host 驻留；native demand 移交会保留一部分已发布范围。该普通路径的有界保留仍是后续候选，不能宣称本轮已修复所有恢复重算来源。

## 三动作补测与负结果

主场景的 3s 等待会被 `min_cold_residency_ms=3000` 判为不值得 DEMOTE；自动短 PIN 也关闭。因此，上述净收益是该生命周期预取策略相对按需组的结果，不能作为三动作同时启用的收益证明。

独立 seed9031 的 30s 等待补测采用两轮×64任务、C32、自动 PIN TTL=1000ms，384 次恢复及控制全部通过。生命周期179.849s、按需175.030s、固定预取175.418s：生命周期工作吞吐 **−2.68%**，未出现重复 prefill；按需重复 prefill 为49152tokens。补测没有计入主场景时长、区间或收益。

[实际范围回执](three-action-effects.json)按 wire ID 去重：89 次 DEMOTE 中，11 次完成回收，累计操作范围180224tokens；13 次部分完成，保存范围受到 GPU 副本或活动引用阻挡；65 次目标缺失。保存范围累计393216tokens。另观察到29个自动PIN子操作，末次回执28个expired、1个released。保存和回收分开报告，没有将受阻范围计为释放。

全部早期筛选、失败和负结果保留在外部归档。较长筛选中，poll50/PIN1000 的工作吞吐为−9.9%；poll250 的+25.3%伴随一条ACK控制失败；复用能力发现后为+11.75%但p95增加53.47%；关闭短PIN后为+11.25%但p95仍增加23.26%。到期准备优先的筛选为+14.52%、p95+4.87%，才选入独立评估。跨版本按需基线自身也有变化，不能将跨版本绝对差全部归因于某个补丁。

早期 `formal-c32` 因取消中的共享 job 冲突终止后续组，1664 次生成一致但17条控制结果失败；原始失败验收保留。自动准备的 typed Conflict 现正常退回，显式操作仍拒绝；ACK 工具仅对精确 non-quiescent 暂拒在原 deadline 内重查，不隐藏其他错误。它们均先通过功能测试，再重新冻结正式配置。独立评估未重新使用该失败输入或成本模型。
