# 附录 F：Qwen3.6-27B 在旧版 SGLang（0.5.1）上推理乱码的根因分析

> 结论先行：乱码不是模型或 FP8 的问题，而是 SGLang 版本远早于 Qwen3.6 架构支持的必然结果。同样的旧版本跑 Qwen3.6-35B-A3B 正常，是因为该模型属于 SGLang 当时已支持的经典 MoE 路线。

## 1. 问题现象

在同一批 L40S（SM89）机器上，用同一套较旧的 SGLang 环境：

| 模型 | 现象 |
|------|------|
| Qwen3.6-27B-FP8 | 推理输出乱码 |
| Qwen3.6-35B-A3B-FP8 | 推理正常 |

两个模型同为 Qwen3.6 家族、同为 FP8 量化，却出现完全相反的结论，直观上会怀疑模型文件或 FP8 兼容性，但真正的原因在版本时间线。

## 2. SGLang 版本时间线

### 2.1 用户环境的实际版本

所谓 "0.5.0" 实际是 **v0.5.1**（0.5.0 从未发布 stable 版）：

| 版本 | 日期 | 说明 |
|------|------|------|
| v0.4.10 | 2025-07-31 | 0.4 系列最后一个 stable |
| v0.5.0rc0 | 2025-08-08 | RC，未出 stable |
| v0.5.0rc1 | 2025-08-13 | RC |
| v0.5.0rc2 | 2025-08-14 | RC |
| **v0.5.1** | **2025-08-23** | 0.5 系列第一个 stable |

佐证：GitHub 发布历史中 v0.5.0rc2 之后直接是 v0.5.1，中间没有 v0.5.0 stable 标签；PyPI 上 `sglang==0.5.0` 返回 404（该精确版本不存在）。所谓 0.5.0 环境，实际对应的是 2025 年 8 月中旬的源码/nightly。

### 2.2 Qwen3.6 架构支持时间线

| 里程碑 | 时间 | 说明 |
|--------|------|------|
| Qwen3-Next（混合线性注意力架构）支持合入 | 2025-09-08 | PR #10233，比 v0.5.1 晚两周 |
| v0.5.3 发布 | 2025-10-06 | 正式带上 Qwen3-Next 支持（含 MTP、DP、多硬件） |
| "Qwen3.6" 进入官方模型支持 | 2026-04/05（v0.5.11） | Day-0 新模型支持名单 |
| 当前生产版本 | 0.5.16 / 0.5.17 | 无此问题 |

## 3. 根因

v0.5.1（2025-08-23）发布时，SGLang 完全没有 Qwen3.6 所需的混合线性注意力（hybrid SSM/Mamba）架构实现，也缺少配套的解析能力。模型加载后只能走通用 fallback：

1. **架构不支持**：27B 的混合线性注意力层没有对应实现，KV/SSM state 处理方式错误；
2. **chat template 不匹配**：Qwen3.6 的 thinking/tool-call template 未注册，按通用模板解析；
3. **parser 缺失**：`--reasoning-parser qwen3`、`--tool-call-parser qwen3_coder` 在当时并不存在；
4. **FP8 布局**：Qwen3Next 的 FP8 量化支持（PR #10466，2025-09-14）同样晚于 v0.5.1。

以上叠加，输出乱码是必然结果，而非偶发故障。

## 4. 为什么 35B-A3B 正常

Qwen3.6-35B-A3B 虽然参数更多（MoE），但属于 SGLang 早已支持的传统 transformer + MoE 路线。旧版本对经典 MoE（fused_moe/triton）的支持成熟，无需新架构代码即可正确加载与推理。

结论：**问题不在模型大小或 FP8，而在 27B 是 SGLang 当时完全不支持的新架构**。同一版本对不同架构的模型表现不同，恰恰印证了这一点。

## 5. 排查与验证建议

如果遇到类似"同一模型不同架构表现迥异"的现象，按此顺序排查：

1. 确认 SGLang 版本：`python3.12 -c "import sglang; print(sglang.__version__)"`
2. 查模型架构支持时间：Qwen3-Next/Qwen3.6 对应的合入 PR 与首个 release
3. 查 parser：`--help | grep -iE "reasoning|tool-call"` 确认 qwen3 相关 parser 是否存在
4. 对照官方 cookbook 的启动参数，避免走通用 fallback
5. 若必须用旧版本，先验证模型本身：单卡、关 MTP、标准 template 跑一条短请求，区分"模型坏了"与"框架不支持"

## 6. 附：0.5.x 其他易踩的破坏性变更

旧脚本迁移到新版本时还应注意（Migration Guide 记录）：

- 环境变量前缀 `SGL_` → `SGLANG_`
- 超时单位由毫秒改为秒
- 部分 FP8/量化相关环境变量废弃，改为 CLI 参数

生产脚本（`sglang_start.sh`）当前已按 0.5.16/0.5.17 版本固化，不受影响。
