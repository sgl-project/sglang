# 第 1 章 从零理解：LLM 推理服务在干什么

> 本章没有任何代码，目标是建立三个直觉：模型怎么"说话"、服务为什么难、SGLang 到底优化了什么。

## 1.1 模型是怎么"说话"的：一个 token 一个 token 地蹦

大语言模型（LLM）本质上是一个"猜下一个词"的函数。给它一段文字，它输出一个概率分布，告诉我们"下一个词最可能是谁"。然后把这个词拼回去，再猜下一个，循环往复。

这里有两个关键事实：

1. **模型不认识字，只认识 token**。token 是文本的分词单元，一个中文词、一个英文单词或子词都可能是一个 token。"今天天气不错" 大概会被切成 5~8 个 token。
2. **生成是逐 token 的**。哪怕最后要输出 500 个字，模型也是一次吐一个 token，这个过程叫**自回归（autoregressive）**。这就是为什么"生成"天生就慢——它没法像翻译一样一次性吐出整句。

## 1.2 为什么"算过的内容"可以缓存：KV Cache 的直觉

猜下一个词的时候，模型要"回顾"前面所有 token。一个朴素实现是每次重新看一遍全部历史——那生成 500 个词要重复处理 500 次前面的内容，谁都受不了。

幸运的是，前面的内容在每一步都会被**重算成同样的中间结果**。把这些中间结果（每层的 Key 和 Value，合称 **KV Cache**）存下来，每一步就只需要处理"最新的那一个 token"。这就是 KV Cache 存在的原因：**拿显存换时间**。

代价也很直观：KV Cache 会随请求长度线性增长，是推理显存的最大开销之一。后面你会反复遇到"显存预算"这个词，它的大头就是 KV Cache。

## 1.3 一个请求的两个阶段：prefill 和 decode

因为 KV Cache，一个生成请求天然分成两个阶段：

| 阶段 | 在干什么 | 特点 |
| --- | --- | --- |
| **prefill（预填充）** | 第一次读完整段 prompt，算出并写入 KV Cache，同时算出第一个输出 token | 计算密集：要处理整段 prompt，像"大厨第一次备一整桌菜" |
| **decode（解码）** | 一个 token 一个 token 地生成，边生成边读自己刚写的 KV Cache | 访存密集：算得少、搬数据多，像"逐道菜上桌" |

这两个阶段对 GPU 的消耗方式完全不同。这个区分是整个推理优化的基石，请务必记住。

## 1.4 服务为什么难：很多人同时来

单用户生成已经慢，多人同时用就更麻烦了。最笨的做法是"一个用户一个 GPU，谁来了谁独占"——贵，而且浪费。

聪明的做法是**批处理（batching）**：把多个请求拼在一起，一次 GPU 前向同时处理多个请求。GPU 很喜欢这种"一次算一堆"的方式。

但批处理有个经典问题：请求的长短、到达时间都不一样。传统做法是"凑满一批再一起跑"，结果后来的请求要干等。现代推理框架用的是**连续批处理（continuous batching）**：

> 类比银行柜台：不是"一批客户全部办完才放下一批"，而是**谁办完谁走，空出来的柜台马上接下一个**。

对 GPU 来说，就是：一个请求生成完了就离开 batch，新请求随时加入。这个机制让 GPU 几乎永远满载，是吞吐的关键。

## 1.5 还能更聪明：复用别人的劳动成果

多轮对话里，用户问"帮我写个报告"，模型答了，用户接着说"再长一点"——第二轮的 prompt 包含第一轮的全部内容。如果每次都要重新 prefill 一遍第一轮，就是重复劳动。

> 类比：餐厅发现"宫保鸡丁"是必点菜，于是提前备好半成品放在冷藏柜，来了直接下锅。**KV Cache 就是那份半成品。**

问题是"半成品"怎么存、怎么找、怎么淘汰。不同请求的前缀五花八门，一个朴素缓存很快就被塞满。这就是 SGLang 标志性技术 **RadixAttention** 的用武之地：它把 KV Cache 组织成一棵前缀树，让**任何两个请求的公共前缀都能共享同一份缓存**。它也是理解本仓库的钥匙之一。

## 1.6 那 SGLang 到底是什么

一句话：**SGLang 是一个把上面这些优化（批处理、KV Cache、前缀复用、显存管理、多机并行）工程化到工业级的高性能 LLM 服务框架。**

它对外提供：

- 一个 HTTP 服务（OpenAI 兼容 API，curl 就能调用）；
- 一个 Python 前端（`sgl.Engine` 等，适合批量处理和 RL 训练）；
- 一整套支撑"吞吐、延迟、显存、多卡"的工程实现。

和训练框架（PyTorch、DeepSpeed）的区别：训练关心"梯度怎么算、权重怎么更新"，而 SGLang 关心"**已经训好的模型怎么以最低成本服务最多请求**"。
