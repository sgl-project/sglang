# Qwen3.x ModelOpt NVFP4 GEMM for SM120

Generated by the Humanize2 workflow
([PolyArch/humanize](https://github.com/PolyArch/humanize)) and
[Kernel Design Agents](https://github.com/mit-han-lab/kernel-design-agents).
Imported from [BBuf/KDA-Pilot PR #195](https://github.com/BBuf/KDA-Pilot/pull/195)
at `516c976cee824a236679adf6eb525275a0a9a120`.

Captured on an NVIDIA RTX PRO 6000 Blackwell Server Edition (SM120). The
skinny-GEMM schedule also covers ModelOpt NVFP4 MLP shapes from Qwen3.5-4B
and Qwen3.5-9B:

- Qwen3.5-4B gate/up: K=2560, N=18432; down: K=9216, N=2560
- Qwen3.5-9B gate/up: K=4096, N=24576; down: K=12288, N=4096
- Qwen3.6/3.8-27B gate/up: K=5120, N=34816; down: K=17408, N=5120
- Qwen3.8-27B lm_head: K=5120, N=248320

The low-level API accepts Qwen3.5 decode rows M in {1, 2, 4, 8, 9}, plus the
captured Qwen3.8 M in {1, 9} decode and M=4369 prefill shapes. ModelOpt
dispatch is narrower: Qwen3.5-4B/9B MLP at M in {1, 2, 4, 8}, and Qwen3.8-27B
down projection at M=9. Every other call falls back to FlashInfer.

Decode serving streams both FP4 weights and weight scales through L2. Persisting
the 5.6--11 MiB scale tensor helped isolated GEMM benchmarks but displaced
attention/SSM state in the full pipeline.

On RTX PRO 6000 with FlashInfer 0.6.18, the 16 production-dispatched Qwen3.5
rows had geometric-mean kernel speedup 1.319x versus FlashInfer. End-to-end
output throughput improved 6.5--8.7% on Qwen3.5-4B and 2.7--3.2% on
Qwen3.5-9B at concurrency 1/2/4/8. Qwen3.8-27B DSpark output throughput went
from 128.35 to 129.60 tok/s with unchanged accept length.
