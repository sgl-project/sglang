# DeepSelect CUDA kernels (vendored)

The kernels under `cuda_kernels/` are vendored from the official DeepSelect
repository (commit `382d62a`, MIT License). The shared sources (`config.h`,
> `common_parts.cuh`, `utils.cuh`, `bit_utils.cuh`, and the three
> `topk_select.{h,cuh}` files) differ from upstream only in trailing
> whitespace, and the `v3_cluster` instantiations are split into `sm90/`
> and `sm100/` subdirectories (upstream keeps all 16 files in one flat
> directory); everything else is unmodified. `../api.cpp` is the SGLang
> adaptation layer.

## Instantiations

Every file in an `instantiations/` directory is generated by the official
repository's `scripts/generate_instantiations.py` and is byte-identical to
its output. Do not hand-edit them: tuning decisions belong to the official
repo, and regeneration rewrites these directories wholesale.

- `v3/` (bf16 normal) and `v3_fp32/` instantiations are tuned per workload
  shape (`num_waves`, top-k tier). Dispatch selects them on every supported
  architecture, so they compile for all of `sm_90a`, `sm_100a`, `sm_103a`.
- `v3_cluster/` instantiations are architecture-specific and split into two
  directories (an SGLang-side split; upstream keeps all 16 files flat):
  - `sm90/`: 8-CTA cluster, the portable maximum. Dispatch selects these
    only on SM90 (`major == 9`, vocab >= 128Ki). Compiled only for `sm_90a`.
  - `sm100/`: 16-CTA cluster (sets
    `cudaFuncAttributeNonPortableClusterSizeAllowed`). Dispatch selects
    these only on SM100/SM103 (`major == 10`, vocab >= 512Ki). Compiled
    only for `sm_100a` and `sm_103a`.

`elements_per_segment` is fixed at 512 upstream and not encoded in the
filenames; all other template arguments are (see the official generator for
the name mapping).

## Picking up upstream tuning changes

Run the official generator, copy the three `instantiations/` trees over,
then move the `*_cluster_8.cu` files into `v3_cluster/instantiations/sm90/`
and the `*_cluster_16.cu` files into `v3_cluster/instantiations/sm100/`
without modifying file content. The `#include "../topk_select.cuh"` line
inside the generated files keeps resolving from the subdirectories because
`v3_cluster/instantiations` is on the include path (see the DeepSelect block
in `python/sglang/kernels/aot/CMakeLists.txt`).
