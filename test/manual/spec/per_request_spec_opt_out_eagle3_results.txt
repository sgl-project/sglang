What the draft-state probes check
- All layers of this one-layer EAGLE3 draft, across the full committed prefix.
- Existing committed K/V values and logical-to-physical mappings remain exactly
  unchanged across successive observed iterations and across draft extend.
- New committed slots have finite K/V values and no within-request aliasing.
- new_seq_lens = old_seq_lens + accept_lens.
- Draft-extend inputs equal retained prediction inputs; the next bonus token is
  the last retained target token. Opt-out counts and acceptance-index sentinels
  are checked by the existing verifier probe.
These are direct state/invariant checks. They do not prove numerical equality
of every new KV value against an independently recomputed draft reference.

Reproduction
Use the pinned image and Rust preflight from prepare_per_request_spec_opt_out_e2e.sh:
  export OPT_OUT_EXPECTED_COMMIT=<reviewed full commit SHA>
  export OPT_OUT_MODELS=Qwen/Qwen3-1.7B,AngelSlim/Qwen3-1.7B_eagle3
  bash test/manual/spec/prepare_per_request_spec_opt_out_e2e.sh prepare
  export PYTHONPATH=python:test/manual/spec
  export SGLANG_CACHE_DIR=/workspace/sglang-47965-cache
  export SGLANG_RUST_BUILD_MODE=never HF_HOME=/workspace/sglang-47965-hf
  export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
  LIFECYCLE_RESULTS=/workspace/eagle3-eager timeout 900 \
    python -u test/manual/spec/test_eagle3_opt_out_lifecycle.py
  LIFECYCLE_RESULTS=/workspace/eagle3-graph LIFECYCLE_GRAPH=1 \
    SGLANG_ENABLE_EAGLE_POST_VERIFY_CUDA_GRAPH=1 timeout 900 \
    python -u test/manual/spec/test_eagle3_opt_out_lifecycle.py

The model names can be overridden with LIFECYCLE_TARGET/LIFECYCLE_DRAFT, but
changing the pair requires separate preparation and invalidates these results.
The script cleans its server processes; the operator must download evidence
and STOP the billable Pod. Do not treat script exit as Pod shutdown.
