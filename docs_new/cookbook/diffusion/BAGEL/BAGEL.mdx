## Overview

[BAGEL-7B-MoT](https://huggingface.co/ByteDance-Seed/BAGEL-7B-MoT) is a
multimodal mixture-of-transformer-experts model from ByteDance Seed. SGLang's
native integration supports text-to-image generation, model-generated planning
before image generation (Thinking), single-image editing, and single-image
Understanding on NVIDIA CUDA.

<Warning>
Run text-to-image generation, Thinking, editing, and Understanding as separate
pipeline processes. Thinking T2I is selected when the process starts;
Understanding reasoning is a per-request option on the dedicated Understanding
process. The current integration does not support editing masks, multiple input
images, multi-output requests, dynamic batching, sequence/CFG parallelism,
Cache-DiT, or layer-wise offload. Transformer tensor parallelism is validated at
TP=2.
</Warning>

## Prerequisites

- Install SGLang Diffusion by following the
  [installation guide](/docs/sglang-diffusion/installation).
- Use one NVIDIA CUDA GPU with enough memory for the BF16 checkpoint and the
  requested image resolution, or two GPUs with TP=2.
- Use the official `ByteDance-Seed/BAGEL-7B-MoT` checkpoint. The examples pin a
  checkpoint revision for reproducibility.

## Start a text-to-image server

Start the OpenAI-compatible image server:

```bash
sglang serve \
  --model-path ByteDance-Seed/BAGEL-7B-MoT \
  --revision 5019f57d168e5816e8f3f701b17cc816bb7cf24b \
  --port 30000
```

You can also pass a local checkpoint directory. SGLang identifies an arbitrary
local directory as BAGEL only when it contains all four root-level files:
`config.json`, `llm_config.json`, `ema.safetensors`, and `ae.safetensors`.
When `BagelUnderstandingPipeline` is selected explicitly, its slim loader only
requires the first three files plus tokenizer assets and does not open
`ae.safetensors`.

## Start an editing server

Select `BagelEditPipeline` explicitly. This process additionally loads the VAE
encoder and BAGEL vision encoder required for image conditioning:

```bash
sglang serve \
  --model-path ByteDance-Seed/BAGEL-7B-MoT \
  --revision 5019f57d168e5816e8f3f701b17cc816bb7cf24b \
  --pipeline-class-name BagelEditPipeline \
  --port 30010
```

One process serves one BAGEL capability. Restart with `BagelPipeline`, or omit
`--pipeline-class-name`, to return to text-to-image generation.

## Start a Thinking server

Select `BagelThinkingPipeline` explicitly. This process loads the checkpoint's
language head, generates a request-local plan, and adds that clean plan to the
image-conditioning context before denoising:

```bash
sglang serve \
  --model-path ByteDance-Seed/BAGEL-7B-MoT \
  --revision 5019f57d168e5816e8f3f701b17cc816bb7cf24b \
  --pipeline-class-name BagelThinkingPipeline \
  --port 30020
```

The baseline T2I and Editing processes do not load the language head. Keeping
Thinking as a separate process therefore avoids adding its roughly 1 GiB BF16
weight to those pipelines.

## Start an Understanding server

Select `BagelUnderstandingPipeline` explicitly. This process loads only the UND
transformer expert, language head, image encoder, and tokenizer. It does not load
the generation expert, VAE, scheduler, or `ae.safetensors`:

```bash
sglang serve \
  --model-path ByteDance-Seed/BAGEL-7B-MoT \
  --revision 5019f57d168e5816e8f3f701b17cc816bb7cf24b \
  --pipeline-class-name BagelUnderstandingPipeline \
  --port 30030
```

The slim Understanding weight set is approximately 15 GiB in BF16 before KV
cache and runtime workspaces. The pipeline applies BAGEL's official outer image
resize before the independent ViT resize, but never runs VAE encode/decode or a
denoising loop.

## Use tensor parallelism

All four BAGEL pipeline variants support TP=2. Transformer attention, MLP, token
embedding, and the optional language head are sharded; the VAE, vision encoder,
and small auxiliary projections remain replicated. Add the same flags to any
server command above:

```bash
sglang serve \
  --model-path ByteDance-Seed/BAGEL-7B-MoT \
  --revision 5019f57d168e5816e8f3f701b17cc816bb7cf24b \
  --num-gpus 2 \
  --tp-size 2 \
  --port 30000
```

## Generate an image

Send a single-output request through the OpenAI-compatible images API:

```python
import base64

from openai import OpenAI

client = OpenAI(api_key="EMPTY", base_url="http://localhost:30000/v1")

response = client.images.generate(
    model="ByteDance-Seed/BAGEL-7B-MoT",
    prompt="Doraemon is eating dorayaki",
    n=1,
    response_format="b64_json",
    size="1024x1024",
    extra_body={
        "seed": 42,
        "num_inference_steps": 50,
        "guidance_scale": 4.0,
        "flow_shift": 3.0,
        "generator_device": "cpu",
    },
)

image_bytes = base64.b64decode(response.data[0].b64_json)
with open("bagel.png", "wb") as output_file:
    output_file.write(image_bytes)
```

For an offline one-shot generation, use the CLI:

```bash
sglang generate \
  --model-path ByteDance-Seed/BAGEL-7B-MoT \
  --revision 5019f57d168e5816e8f3f701b17cc816bb7cf24b \
  --prompt "Doraemon is eating dorayaki" \
  --height 1024 \
  --width 1024 \
  --seed 42 \
  --num-inference-steps 50 \
  --guidance-scale 4.0 \
  --save-output
```

The default BAGEL flow shift is `3.0`. The images API accepts `flow_shift` as a
request field; the offline CLI uses the model default. The fixed-seed example
uses the CPU generator to match the official BAGEL noise initialization.

## Generate an image with Thinking

Send the same Images API request to the Thinking server and optionally control
the planning decode through `extra_body`:

```python
from openai import OpenAI

client = OpenAI(api_key="EMPTY", base_url="http://localhost:30020/v1")

response = client.images.generate(
    model="ByteDance-Seed/BAGEL-7B-MoT",
    prompt="Doraemon is eating dorayaki",
    n=1,
    response_format="b64_json",
    size="1024x1024",
    extra_body={
        "seed": 42,
        "num_inference_steps": 50,
        "guidance_scale": 4.0,
        "max_think_tokens": 1000,
        "think_do_sample": False,
        "think_temperature": 0.3,
    },
)

print(response.data[0].revised_prompt)
```

`revised_prompt` contains the original prompt, a newline, and BAGEL's generated
planning text—the text actually added to the image-conditioning context. The
default decode is greedy, so `think_temperature` is used only when
`think_do_sample=true`. `max_think_tokens` counts the initial
`<|im_start|>` iteration, matching the official BAGEL implementation.

For offline generation, select the same pipeline explicitly:

```bash
sglang generate \
  --model-path ByteDance-Seed/BAGEL-7B-MoT \
  --revision 5019f57d168e5816e8f3f701b17cc816bb7cf24b \
  --pipeline-class-name BagelThinkingPipeline \
  --prompt "Doraemon is eating dorayaki" \
  --height 1024 \
  --width 1024 \
  --seed 42 \
  --max-think-tokens 1000 \
  --think-temperature 0.3 \
  --num-inference-steps 50 \
  --guidance-scale 4.0 \
  --save-output
```

## Edit an image

Send one source image to the editing server through the OpenAI-compatible
images edits API. Omit `size` to preserve the source aspect ratio with BAGEL's
official resize policy:

```python
import base64

from openai import OpenAI

client = OpenAI(api_key="EMPTY", base_url="http://localhost:30010/v1")

with open("input.png", "rb") as input_image:
    response = client.images.edit(
        model="ByteDance-Seed/BAGEL-7B-MoT",
        image=input_image,
        prompt="Turn the background into a blue sky",
        n=1,
        response_format="b64_json",
        extra_body={
            "seed": 42,
            "num_inference_steps": 50,
            "guidance_scale": 4.0,
            "true_cfg_scale": 2.0,
        },
    )

image_bytes = base64.b64decode(response.data[0].b64_json)
with open("bagel-edit.png", "wb") as output_file:
    output_file.write(image_bytes)
```

For an offline edit, use the same explicit pipeline selection:

```bash
sglang generate \
  --model-path ByteDance-Seed/BAGEL-7B-MoT \
  --revision 5019f57d168e5816e8f3f701b17cc816bb7cf24b \
  --pipeline-class-name BagelEditPipeline \
  --image-path input.png \
  --prompt "Turn the background into a blue sky" \
  --seed 42 \
  --num-inference-steps 50 \
  --guidance-scale 4.0 \
  --true-cfg-scale 2.0 \
  --save-output
```

`guidance_scale` controls text CFG. `true_cfg_scale` controls BAGEL's image CFG
and defaults to `2.0` when omitted. Transparent inputs are composited on a
white background before encoding, matching the official application path.

## Understand an image

Send one image and one prompt through the non-streaming OpenAI-compatible Chat
Completions API:

```python
import base64

from openai import OpenAI

client = OpenAI(api_key="EMPTY", base_url="http://localhost:30030/v1")

with open("input.png", "rb") as input_file:
    image_data = base64.b64encode(input_file.read()).decode("utf-8")

response = client.chat.completions.create(
    model="ByteDance-Seed/BAGEL-7B-MoT",
    messages=[
        {
            "role": "user",
            "content": [
                {
                    "type": "image_url",
                    "image_url": {"url": f"data:image/png;base64,{image_data}"},
                },
                {"type": "text", "text": "Describe this image."},
            ],
        }
    ],
    max_completion_tokens=511,
    temperature=0,
)

print(response.choices[0].message.content)
```

The public default is greedy with a BAGEL `max_new_tokens` value of `512`.
BAGEL counts the initial `<|im_start|>` decode iteration, so the default permits
at most 511 content tokens. Set `reasoning_effort="high"` or pass
`extra_body={"chat_template_kwargs": {"enable_thinking": True}}` through the
OpenAI Python SDK to prepend the official VLM reasoning system prompt. The
returned assistant message remains one string that contains both
`<think>...</think>` and the answer.

For offline Understanding, the CLI prints the response to stdout:

```bash
sglang generate \
  --model-path ByteDance-Seed/BAGEL-7B-MoT \
  --revision 5019f57d168e5816e8f3f701b17cc816bb7cf24b \
  --pipeline-class-name BagelUnderstandingPipeline \
  --image-path input.png \
  --prompt "Describe this image." \
  --max-new-tokens 512 \
  --seed 42
```

## Current request contract

- Send one prompt and request one output (`n=1`).
- Use an empty or omitted negative prompt. BAGEL's initial T2I path does not
  implement negative-prompt conditioning.
- Use `num_inference_steps=50` to execute 50 denoising updates.
- Keep `guidance_scale=4.0` and `flow_shift=3.0` for the official default path.
- Thinking uses the official three-way context: system + prompt + plan, system
  only, and system + prompt. Its secondary CFG scale is fixed at `1.5`.
- Thinking defaults to greedy planning. Add `think_do_sample=true` in HTTP or
  `--think-do-sample` offline to use request-local seeded sampling.
- Editing accepts exactly one source image and no mask. Omit `size` for
  automatic official resizing; if supplied, it must equal the calculated
  preprocessed size.
- Understanding accepts exactly one image and one non-empty prompt. It returns
  text directly and does not execute image denoising or decoding stages.
- Understanding defaults to greedy decode. Positive Chat Completions
  `temperature` enables request-local seeded sampling; offline callers can use
  `--do-sample --temperature VALUE`.

See the [BAGEL repository](https://github.com/ByteDance-Seed/Bagel) for the
upstream model implementation and the
[SGLang Diffusion API guide](/docs/sglang-diffusion/api/openai_api) for endpoint
details.
