# 组会讲稿（对应 组会汇报_创新点12.pptx，约 10-12 分钟）

> 每页 2-4 句口播要点。黑体句是每页的"带走信息"。

**P1 封面**：两句话开场——上次组会定的是三个创新点；今天汇报前两个的完成情况，第三个做了可行性评估。

**P2 本次汇报**：创新点 1 是"做完并验收"；创新点 2 是"做完但发现结论和预期不一样"——这个意外反而是今天最有价值的部分。贯穿结论：**对 Agent serving，KV 容量是一阶杠杆，策略是二阶杠杆。**

**P3 动机**：24GB 卡跑 4B 模型，BF16 KV 把容量锁死在 9.4 万 token；一条 Agent 会话就吃 10-30%。现有 FP4 方案都绑在 sm90+ 上，sm86 没有基础设施——所以全链路自研。

**P4 方案**：存储按 MXFP4 标准（E2M1 打包 + block32 E8M0），RNE 舍入；decode 不走"反量化落盘再算"，融合 kernel 直接读 fp4，零额外带宽。以 `--kv-cache-dtype fp4_mx_block32` 一行接入，生产配置全开。

**P5 kernel 演进**：第一代标量版 TPOT +26% 超标；第二版想用张量核，先手工构造 fragment 惨败（慢 2.1×），后来逐条确认 PTX ISA 的 ldmatrix 语义后重写——0.677ms，比标量快 20%。图上和 flashinfer fp16 的差距就是 fp4 反量化的固有 ALU 成本。附一个精度教训：张量核路径里 softmax 分子分母必须同源舍入，否则 GSM8K 掉 2.7 个点（有消融）。

**P6 端到端验收**：生产配置（graph/radix/overlap 全开）下全部达标——精度 89.2%、TPOT +16.2%、TTFT +7.3%，容量 3.03×。一句话：反量化 ALU 是固有开销，换来 3 倍容量；这个交换值不值，创新点 2 给了定量答案。

**P7 Agent 能力边界**：用 BFCL 测 Agent 能力。单轮持平，multi_turn_base 掉 12.5pt——fp4 KV 的误差在 8k-26k 多轮里累积，失败表现为工具调用循环。我们的 BF16 复现和官方榜单逐位吻合，说明管线可信。这条如实写进论文：是量化 KV 的能力边界。

**P8 创新点 2 动机**：工具执行期（0.1s~30s）KV 前缀被驱逐，返回后重算；8k 前缀重算 2-4s、命中只要 0.1-0.3s。直觉方案是预测返回时间做保留（Continuum 用 TTL pin）。但发现一个空白：**现有 benchmark 的工具执行是瞬时的，测不出这类策略**——所以先造了测量工具。

**P9 harness**：标准 tool-calling 回路 + 注入延迟 + N 路并发；工具混合是指定的（4 类 lognormal），上下文精确控长。命中/未命中差 100 倍，信号非常干净。

**P10 主图（重点讲）**：横轴并发会话数。蓝线 BF16：N=16 就开始掉，N=32 崩溃（81% miss、TTFT 15.6 秒）；橙线 MXFP4 同负载 17.7% / 0.30 秒——**50 倍**。MXFP4 自己的崩溃点在 56-64。结论：**容量把 serving 从崩溃区搬回正常区，2-3× 可持续并发包络**。

**P11 三区模型 + 负结果**：用"需求速率÷池容量"单一变量分成三区：可容纳、边际、深饱和。我们的 gap 感知驱逐在边际带有弱收益（3 seed 一致 -15%），但**没有稳健胜过 LRU**——机理：agent 负载下访问新近度≈会话翻转率，LRU 已经隐式做了对的事。对 Continuum 的对照意义：radix 开着的引擎上 retention headroom 很小。

**P12 总结/下一步**：两个创新点闭环；创新点 3（预取）物理账成立（重载比重算便宜 15-25×），但有个生死问题（HiCache 按需恢复的成本）要用 1-2 小时实验判定；素材齐备，进入论文写作。

## 可能被问的问题（备答）

- **精度 89.2% 够吗？** 验收线 90% 是 block16 时代定的；block32 是 MXFP4 标准，接受 ~89%，且 BFCL 显示长上下文是真实边界——这是我们下一步（block16 挽回实验）的备选。
- **TPOT +16% 的来源？** kernel 级数据支撑：反量化 ALU 固有成本（0.677 vs 0.474ms），上层调度零回归（同栈同配置）。
- **为什么不用 Continuum 的 TTL？** 我们实现了纯排序版并做了 3 seed 对照：radix-LRU 之上 headroom 很小（弱信号 -15%）；Continuum 的大收益是相对 vLLM 弱前缀缓存的。
- **harness 可信吗？** 数据集结构复用 BFCL 真实任务；延迟表手工标定 + 敏感性分析；BF16 复现官方分数验证过 BFCL 管线。
