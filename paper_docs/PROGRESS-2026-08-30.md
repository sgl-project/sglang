## 3. 关键洞察:LRU 在 agent 负载下方向反了(论文核心论点)

经典缓存 LRU 假设"最近用过 = 马上再用"。agent 会话恰好相反:
**刚结束 action turn = 正在等待外部工具 = 还要隔 gap_s 才回来**,而且 gap
由工具延迟分布决定(**可预测**——这是与经典缓存负载的本质区别)。

- LRU 优先驱逐 last_access_time 最小的 = **离返回最近的会话** → 快工具会话
  被反复驱逐重算(thrashing),慢工具(run_tests)会话反而多活很久
- 最优(Belady 式,gap 可知)= 驱逐 expected_next_access 最远的 = **刚开始长工具等待的会话**
- v0 策略:`evict_key = −(last_access_time + E[gap|tool])`;工具身份从输出文本的
  `<tool_call>` token 序列识别(scheduler 侧,无需 IPC);`E[gap|tool]` 支持在线
  EMA 学习(会话返回时 elapsed 可观测)
