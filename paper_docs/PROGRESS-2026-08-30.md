## 3. 关键洞察:LRU 在 agent 负载下方向反了(论文核心论点)

经典缓存 LRU 假设"最近用过 = 马上再用"。agent 会话恰好相反:
**刚结束 action turn = 正在等待外部工具 = 还要隔 gap_s 才回来**,而且 gap
由工具延迟分布决定(**可预测**——这是与经典缓存负载的本质区别)。

- LRU 优先驱逐 last_access_time 最小的 = **离返回最近的会话** → 快工具会话
  被反复驱逐重算(thrashing),慢工具(run_tests)会话反而多活很久
- 最优(Belady 式,gap 可知)= 驱逐 expected_next_access 最远的 = **刚开始长工具等待的会话**
- v0 策略:`evict_key = −(last_access_time + E[gap|tool])`;工具身份从输出文本的
  `<tool_call>` token 序列识别(scheduler 侧,无需 IPC);`E[gap|tool]` 支持在线
  EMA 学习(会话返回时 elapsed 可观测)

### 核心发现:三区模型(论文骨架)

1. **可容纳区(超卖 <1×)**:fp4 N=32 时 200k 活跃集装进 280k 池 →
   bf16 同负载 miss 81%→**17.7%**,TTFT p50 **15s→303ms(50×)**——
   **容量本身就是最大的 Agent 提速手段**;残余 miss 来自 gap 期 churn + 分类噪声
2. **边际区(1×~1.4×)**:排序决定谁幸存 → Score 稳定赢
   (bf16 N=16:-23% miss;fp4 N=32:-24% miss/-31% 浪费;quick-tool miss→0)
3. **深饱和区(>1.4×)**:容量硬顶,任何排序无效,clamp 保护反而挤占容量
   (Score 反超 LRU)→ 需要**压力感知自适应降级**(future work:miss 率反馈
   或队列深度触发回退 LRU)

工程含义:MXFP4 与 Score 驱逐是**互补而非竞争**——量化把工作负载从崩溃区搬进
可容纳/边际区,排序在边际区优化剩余冲突。 sustainable concurrency 包络:
bf16 ≈ 40 路(13.5% miss)→ fp4+Score ≈ 120+ 路(同 miss 水平),~3×。

### 诚实声明(论文里要写的)

- 深饱和区 Score 劣于 LRU 是当前实现的真实缺陷(保护失效机制已定位,
  自适应降级未实现)
- fp4 组 miss 分类器在深队列下有偏差,绝对值偏低估驱逐
- seed 单次;seed=8 重复在跑

### 为什么 LRU 难被击败(机理解释,论文讨论节)

标定混合下,quick 会话翻转周期 ~1-2s、slow 会话 ~11-30s——**访问新近度与
返回频率强相关,LRU 已隐式近似"保护高频返回会话"**(≈Belady 在该负载下的
可学习部分)。真正的 gap 知识只剩小残差;而我们的实现有结构性 handicap:
预测会过期/滞后(LRU 的信号永远新鲜)。v2 实验(97% quick 均匀混合,LRU
51% miss)展示的"LRU 失效"是同质负载特例——同翻转率下 recency 无频率信号,
但此时也没有任何可预测信息(所有 gap 相同),排序无从获益,**唯一杠杆是容量**。

### 重构后的论文叙事(创新点2 的可交付形态)

1. **主贡献(稳健、跨 seed 复现):KV 容量的 regime-shift 效应**
   bf16 N=32: miss 81-84%、TTFT p50 15.6s(serving 崩溃)→ fp4 N=32:
   miss 18-19%、TTFT 0.30s(**50×**)。可持续 Agent 并发包络 ~3×。
   容量是 Agent serving 的第一序杠杆——这个结论直接回应"量化 KV 换内存
   值不值"的领域问题,且与创新点1 天然一体。
2. **表征研究(方法论贡献):trace-driven 压测 harness + 三区模型**
   (可容纳/边际/深饱和;超卖比 1×/1.4× 分界)。现有 benchmark(BFCL 等)
   工具瞬时执行、无压力,测不出这些现象。
3. **负结果+机理(讨论节,有洞察价值)**:gap 感知驱逐(Continuum 式)在
   radix-LRU 之上的真实 headroom 很小(≤16%,不稳健)且限于边际带;
   LRU 的新近度在 agent 负载下隐式携带频率信息。**这对 Continuum 类工作
   是个清醒的对照**:SGLang 式 radix 缓存已捕获大部分 retention 收益,
   Continuum 相对 vLLM(前缀缓存弱)的大收益不能外推到 radix-on 引擎。
4. future work:压力感知自适应降级(深饱和回退 LRU)、queue-aware TTL、
   连续延迟分布下的学习排序。
