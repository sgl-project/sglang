DM05 maps RGB camera images, a task instruction, and robot state to a continuous
action chunk. SGLang serves it through `multimodal_gen`: a Gemma3 multimodal
prefix encoder produces per-layer K/V, then a time-conditioned action expert
runs the flow-matching loop. The runtime owns checkpoint loading, action
sampling, preprocessing, and postprocessing; it does not require an OpenDM
installation or start a separate language-model server.

## Install

Use Linux with an NVIDIA CUDA GPU and install SGLang's diffusion dependencies:

```bash
git clone https://github.com/sgl-project/sglang.git
cd sglang
pip install -e "python[diffusion]"
```

The implementation uses the Transformers Gemma3 components included with
SGLang's dependency versions. Run one GPU per worker. Tensor, sequence, CFG, and
disaggregated parallelism are not supported for DM05; use independent server
replicas when deploying on multiple GPUs.

## Choose a checkpoint

Each registered checkpoint selects its own deployment recipe. Keep the weights,
processor, normalization statistics, camera names, and action horizon together.

| Checkpoint | Camera keys, in order | State dimensions | Returned action shape | Parameter precision |
| --- | --- | ---: | --- | --- |
| `Dexmal/DM05` | `head`, `left_wrist`, `right_wrist` | 14 | `[50, 14]` | BF16 |
| `Dexmal/DM05-libero` | `head`, `left_wrist` | 8 | `[10, 7]` | BF16 |
| `Dexmal/DM05-robotwin2` | `head`, `left_wrist`, `right_wrist` | 14 | `[50, 14]` | BF16 |
| `Dexmal/DM05-MEM-Robodojo-Sim` | `head`, `left_wrist`, `right_wrist` | 14 | `[50, 14]` | FP32 with BF16 autocast |

The released LIBERO checkpoint's deployment horizon is **10**, even when its
serialized configuration contains `chunk_size: 50`. The MEM recipe uses up to
20 history images and the released Robodojo simulation prompt and normalization
settings. It is distinct from the OpenDM MEM training demo.

All recipes use 10 denoising steps by default and an internal padded action
dimension of 32. The response crops and denormalizes actions to the selected
robot's output dimensions. Parameter precision describes stored runtime weights;
it does not mean every intermediate operation has that dtype.

## Start the server

Serve the LIBERO policy on one GPU:

```bash
CUDA_VISIBLE_DEVICES=0 sglang serve Dexmal/DM05-libero \
  --model-type diffusion \
  --host 127.0.0.1 \
  --port 30000
```

You can use `--revision` to pin a Hugging Face checkpoint revision. For a local
export with an arbitrary directory name, select the matching recipe explicitly:

```bash
CUDA_VISIBLE_DEVICES=0 sglang serve /path/to/libero-checkpoint \
  --model-type diffusion \
  --model-id DM05-libero \
  --host 127.0.0.1 \
  --port 30000
```

Keep `config.json`, the safetensors weights, tokenizer and processor assets,
chat template, and `norm_stats.json` in that checkpoint directory. Loading checks
the complete checkpoint key and tensor-shape contract. Unknown or missing robot
normalization profiles produce an error.

## Generate actions

Read `GET /v1/actions/metadata` for the loaded policy's camera keys, dimensions,
defaults, and transport capabilities. This example sends two RGB images and an
eight-dimensional LIBERO state in the checkpoint's original units:

```python
import base64
import io

import numpy as np
import requests
from PIL import Image


def png_payload(image):
    buffer = io.BytesIO()
    Image.fromarray(image).save(buffer, format="PNG")
    return {"b64_json": base64.b64encode(buffer.getvalue()).decode()}


image = np.zeros((256, 256, 3), dtype=np.uint8)
payload = {
    "input": {
        "task": "pick up the black bowl",
        "observation": {
            "images": {
                "head": png_payload(image),
                "left_wrist": png_payload(image),
            },
            "state": np.zeros(8, dtype=np.float32).tolist(),
        },
    },
    "parameters": {"seed": 7, "num_inference_steps": 10},
    "runtime": {"output_format": "list", "return_timing": True},
}
response = requests.post(
    "http://127.0.0.1:30000/v1/actions/generations",
    json=payload,
    timeout=120,
)
response.raise_for_status()
actions = np.asarray(response.json()["data"][0]["action"]["values"])
print(actions.shape)  # (10, 7)
```

Supply every configured camera in RGB order. Images can also be HWC arrays or
tensor objects with `dtype`, `shape`, and `values`. Send raw state values once;
the server applies the checkpoint's normalization and inverse action transforms.
For the base model, supply `input.observation.robot_type`, `control_mode`, and
`speed` for the intended pretraining condition, for example `DOS W1`, `joint`,
and `"0.5"`.

| Optional field | Behavior |
| --- | --- |
| `input.observation.noise` | Initial noise with shape `[horizon, 32]`, including padded dimensions. Overrides seed-based noise generation. |
| `input.observation.history_images` | Oldest-to-newest RGB frames for the MEM recipe. Missing history slots are padded and masked. |
| `parameters.action_horizon`, `parameters.action_dim` | Must match the loaded deployment's horizon and internal dimension. |
| `runtime.cuda_graph` | Enables the bounded action-loop CUDA Graph cache. Prefix prefill remains eager. |
| `runtime.prefix_cache` | Enables exact prefix lookup when the deployment's `enable_global_prefix_cache` configuration is enabled. |

The shared action API also provides MsgPack HTTP, the generic
`/v1/actions/realtime` WebSocket, and the OpenPI-compatible `/openpi/policy`
WebSocket. Use the loaded DM05 camera and state names with those transports;
the transport does not change the checkpoint's preprocessing or control
conventions. See the [action transport examples](/cookbook/vla/OpenPI/Pi0.5).

## Validate a deployment

Compare identical images, state, prompt, and explicit initial noise when checking
against OpenDM. Retain the complete normalized `[horizon, 32]` tensor before
postprocessing as well as the returned robot actions. Changes to Torch,
Transformers, attention backends, or parameter precision can change floating
point results; matching an API shape or a single deterministic request does not
establish benchmark success rate.

For LIBERO evaluation, use the released checkpoint's 10-action chunk and the
official DM05 benchmark's 10-step replanning interval, image orientation, state
construction, and gripper convention. Keep these settings fixed across the
reference and SGLang evaluations.
