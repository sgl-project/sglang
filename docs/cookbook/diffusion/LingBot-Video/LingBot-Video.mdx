## 1. Model Introduction

LingBot-Video is a Mixture-of-Experts video diffusion model from inclusionAI. The 30B checkpoint activates 3B parameters per token, and one set of weights covers three tasks: text-to-video, image-to-video, and text-to-image.

Two differences from the other video recipes:

- **Qwen3-VL is the text encoder.** For image-to-video the condition frame is passed to the encoder as an image, so the caption and the reference frame are encoded together rather than through a separate image encoder.
- **Prompts are structured JSON captions**, not free text. See [Prompt format](#4-prompt-format).

An optional second pass (the refiner) re-denoises the clip at a higher resolution with a separate set of DiT weights.

## 2. SGLang-diffusion Installation

Please refer to the [official SGLang-diffusion installation guide](/docs/sglang-diffusion/installation) for installation instructions.

## 3. Deployment

```bash Command
sglang serve --model-path robbyant/lingbot-video-moe-30b-a3b
```

One GPU is enough to bring the model up: the DiT is offloaded to CPU between uses by default, and the text encoder, image encoder, and VAE are offloaded layer by layer. `--performance-mode speed` keeps the DiT resident instead, which needs enough memory for all 30B parameters.

Across multiple GPUs, sequence parallelism splits the joint video and text sequence:

```bash Command
sglang serve \
  --model-path robbyant/lingbot-video-moe-30b-a3b \
  --num-gpus 4 \
  --ulysses-degree 4
```

Sequence parallelism splits the sequence, not the weights, so every rank still holds all 30B parameters. When that does not fit, shard the weights as well with `--dit-layerwise-offload` or `--use-fsdp-inference true`; otherwise the DiT runs out of memory as it is placed on device.

`--tp-size`, `--ulysses-degree`, `--ring-degree`, and CFG parallel can be combined, except that image conditioning does not support sequence parallelism (see 5.2). `num_attention_heads` divided by `--tp-size` must stay divisible by `--ulysses-degree`; the server refuses the configuration at startup otherwise. The full list of supported optimizations is in the [compatibility matrix](/docs/sglang-diffusion/compatibility_matrix).

`torch.compile` is not enabled by default for this model, including under `--performance-mode speed`. Benchmark it on your own hardware before enabling it: whether it pays off depends on the GPU.

## 4. Prompt format

The model is trained on structured JSON captions. A raw natural-language prompt is out of distribution and produces degraded output rather than an error, so pass a JSON object:

```json Example
{
  "comprehensive_description": {
    "scene_content_description": "A red fox trots across fresh snow in a pine forest at sunrise, its coat bright against the white ground.",
    "camera_movement_description": "The camera stays stationary at eye level in a medium shot."
  },
  "camera_info": {
    "color": "Warm",
    "frame_size": "Medium",
    "shot_type_angle": "Eye level",
    "lens_size": "Medium",
    "composition": "Center",
    "lighting": "Soft light",
    "lighting_type": "Daylight"
  },
  "world_knowledge": [],
  "prominent_elements": [
    {
      "name": "red fox",
      "description": "A fox with a dense orange-red coat and a white-tipped tail.",
      "actions": [
        { "timestamp": "[0.0s - 1.5s]", "action": "trots from the left toward the center" },
        { "timestamp": "[1.5s - 3.0s]", "action": "pauses to sniff the air, then continues" }
      ],
      "location": "center of the frame",
      "relative_size": "dominant"
    }
  ]
}
```

`comprehensive_description` and `camera_info` are objects, not strings, and each entry in `prominent_elements` carries timestamped actions. A caption with the right keys but flatter values is still out of distribution. The rewriter below emits this shape, so use it rather than writing the JSON by hand.

### 4.1 Prompt rewriter

Rather than writing the JSON by hand, use the rewriter the model was released with. It runs in two turns: expand the free-text prompt into a detailed caption on the base VLM, then map that caption to JSON with the rewriter LoRA enabled. The weights are `Qwen/Qwen3.6-27B` plus `robbyant/lingbot-video-rewriter-lora`, a second model rather than part of the checkpoint.

The rewriter has no CLI flags, so configure it in a config file:

```bash Command
cat > /tmp/lingbot_rewriter.json <<'EOF'
{
  "model_path": "robbyant/lingbot-video-moe-30b-a3b",
  "prompt": "A red fox trots across fresh snow in a pine forest.",
  "num_frames": 81,
  "rewriter_model_path": "Qwen/Qwen3.6-27B",
  "rewriter_adapter_path": "<path to lingbot-video-rewriter-lora>"
}
EOF

sglang generate --config /tmp/lingbot_rewriter.json --save-output
```

This loads the VLM in the diffusion process and switches the adapter between turns, which is what the reference implementation does. It holds roughly 54 GB in bf16 on top of the DiT, and it has no offload path, so give it its own GPUs through `rewriter_device_map` or use the served option below. Note that an under-provisioned VLM degrades quietly rather than failing.

To serve the rewriter separately instead, set `rewriter_url` and name a model per turn:

```json
{
  "rewriter_url": "http://127.0.0.1:30000",
  "rewriter_expand_model": "Qwen/Qwen3.6-27B",
  "rewriter_map_model": "lingbot-rewriter"
}
```

The mapping turn needs the adapter applied. `--lora-paths` does not accept this adapter: `Qwen/Qwen3.6-27B` is a `qwen3_5`-architecture checkpoint whose attention projections SGLang loads fused, while the adapter targets them unfused through a regex. So serve a checkpoint with the adapter already merged in, as its own endpoint via `rewriter_map_url` when one server cannot hold both.

Prompts that already start with `{` are passed through untouched. If the mapping turn returns nothing parseable the request fails rather than falling back to the free-text prompt, which the DiT would render as a broken video. Setting `rewriter_model_path` without `rewriter_adapter_path` is rejected at startup, since the mapping turn would otherwise silently run base weights. Leaving both `rewriter_url` and `rewriter_model_path` unset, the default, skips the stage.

Set `"rewriter_auto_negative": true` to also prune the negative prompt per request, which requires one of the two backends above. The shipped negative is deliberately over-complete and self-contradictory, so terms this caption legitimately wants push the sample away from the request. The rewriter deletes those terms and keeps the rest verbatim; a few, such as `underexposed` for a night scene and `motion blur` for a long exposure, are also deleted by rule afterwards because the model tends to leave them in. Because a merged request carries one negative prompt for several captions, enabling this turns dynamic batching off for the server.

## 5. Generation

### 5.1 Text-to-video

```bash Command
sglang generate \
  --model-path robbyant/lingbot-video-moe-30b-a3b \
  --prompt '{"comprehensive_description": "A red fox trots across fresh snow in a pine forest."}' \
  --num-frames 81 \
  --save-output \
  --output-path outputs
```

Defaults are 81 frames at 480x480 and 16 fps, 40 denoising steps, guidance scale 6.0, and flow shift 3.0. `num_frames` must be 1 or `4n+1`, and height and width must be multiples of 16.

### 5.2 Image-to-video

Pass a condition image; the first frame is pinned to it for the whole denoising loop.

```bash Command
sglang generate \
  --model-path robbyant/lingbot-video-moe-30b-a3b \
  --prompt '{"comprehensive_description": "The fox lifts its head and looks toward the camera."}' \
  --image-path fox.png \
  --num-frames 81 \
  --save-output \
  --output-path outputs
```

Image conditioning does not support sequence parallelism yet. Serve with `--ulysses-degree 1 --ring-degree 1` for image-to-video requests; the server raises an error rather than generating a corrupted clip.

### 5.3 Text-to-image

`--num-frames 1` produces a still image. The request keeps its own negative prompt, which drops the motion and temporal-stability terms that only apply to video, and frame-count alignment is disabled so a single frame is not rounded up into a short clip.

```bash Command
sglang generate \
  --model-path robbyant/lingbot-video-moe-30b-a3b \
  --prompt '{"comprehensive_description": "A red fox sitting in fresh snow, morning light."}' \
  --num-frames 1 \
  --save-output \
  --output-path outputs
```

### 5.4 Refiner second pass

The refiner decodes the base clip, resizes it to the refiner resolution, re-encodes it, and denoises again from `t_thresh` down using the DiT weights in the checkpoint's `refiner` subfolder. Opt in with:

```bash Command
sglang serve \
  --model-path robbyant/lingbot-video-moe-30b-a3b \
  --pipeline-class-name LingBotVideoRefinerPipeline
```

This loads a second set of DiT weights, so the checkpoint on disk and the peak memory both roughly double. Defaults for the second pass are 1088x1920, guidance scale 3.0, flow shift 3.0, and `t_thresh` 0.85. The step count is 8: `refiner_num_inference_steps` lays out a grid from which only the sigmas at or below `t_thresh` are kept, 6 at these defaults, and `refiner_sigma_tail_steps` appends 2 more at the low end. The refiner is trained on video and rejects single-frame requests; serve the base pipeline for text-to-image.

## 6. Benchmark

Test environment:

- Hardware: NVIDIA H100 80GB (8x)
- Model: `robbyant/lingbot-video-moe-30b-a3b`
- Reference: the upstream `lingbot-video` diffusers implementation (diffusers 0.39.0)
- Workload: 480x832, 121 frames, 40 steps, guidance scale 3.0, flow shift 3.0, seed 42, structured JSON caption

Both stacks ran the same caption, resolution, frame count, schedule, and seed, and both computed the two CFG branches sequentially.

| Stack | Parallelism | Denoise | Per step | End to end |
| --- | --- | --- | --- | --- |
| upstream diffusers | FSDP 8 | 409 s | 10.23 s | 469 s |
| SGLang | `--ulysses-degree 8` | 73 s | 1.83 s | 175 s |

SGLang denoises 5.6x faster and completes the request 2.7x faster. End to end covers text encoding, denoising, and VAE decode, so it closes less than denoise alone: both stacks decode the same 121 frames.

The two rows shard differently, so for a weights-only comparison against upstream FSDP, SGLang `--tp-size 8` denoises the same workload in 139 s, 3.48 s per step — still 2.9x faster.

Output matches the reference in subject, composition, and motion without being bit-identical: PSNR 20.7 dB and SSIM 0.82 on the luma plane. Switching only the sharding layout within SGLang moves the result by the same margin, so the difference is the bf16 reduction-order floor across 40 steps.

Other tasks, same hardware and schedule:

| Task | Parallelism | Denoise | Decode |
| --- | --- | --- | --- |
| Text-to-image (1 frame) | `--ulysses-degree 8` | 31.8 s | 0.2 s |
| Image-to-video (121 frames) | `--tp-size 8` | 134 s | 4.7 s |
| Refiner, both passes | `--ulysses-degree 8` + FSDP | 57 s + 100 s | 7.5 s |

Tensor parallelism is the slower layout because the MoE experts are replicated on every rank rather than sharded: `--tp-size 8` splits the attention projections, but each rank still runs all 128 experts. Prefer sequence parallelism, and use tensor parallelism for image-to-video, where sequence parallelism is unavailable.

### 6.1 Recommended configuration

On 8 GPUs:

- Text-to-video and text-to-image: `--ulysses-degree 8`.
- Image-to-video: `--tp-size 8`. Sequence parallelism is rejected for image conditioning, so tensor parallelism is the way to shard.
- Refiner: `--ulysses-degree 8 --use-fsdp-inference true`. Sequence parallelism replicates both sets of DiT weights on every GPU; FSDP shards them, which is what keeps the second pass inside memory at 1088x1920. The refiner tiles the VAE for its own decode and re-encode regardless of `--vae-tiling`.

The model uses CFG, so `--enable-cfg-parallel` is also available: it runs the two guidance branches on separate GPU groups and halves the sequence-parallel group size. Whether that beats pure Ulysses depends on interconnect bandwidth, so benchmark both on your own topology. Cache-DiT does not support this model.

## 7. Notes

- The refiner conditions on zeros rather than on the negative prompt, and reseeds instead of continuing the base pass random stream.
- Text-only requests batch normally. Image requests are kept out of batches by the scheduler.
- Latents stay fp32 through the denoising loop while the DiT bulk runs in bf16; the norms, router, and timestep embedder are pinned to fp32.
