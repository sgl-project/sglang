## 2. Model capabilities

[HiDream-O1-Image](https://huggingface.co/HiDream-ai/HiDream-O1-Image) is an 8B pixel-level Unified Transformer (UiT). Unlike the usual latent-diffusion layout, it has neither a VAE nor a separate text encoder: one Qwen3-VL backbone embeds the prompt and predicts clean 32x32 RGB patches directly, and the flow-matching head reads its timestep from a dedicated token in the prompt. It loads through SGLang's native `HiDreamO1ImagePipeline`.

Choose it for generation at its trained 2K-class resolutions, including legible in-image text. The checkpoint ships a stock `qwen3_vl` config with no `model_index.json`, so the pipeline loads the model itself. All three checkpoints run the same generation stage, so the full model also supports TI2I editing, `--pe-server-url` prompt enhancement, multi-prompt batching, and cache-dit — the remaining per-variant surface is the recipe (bf16 vs fp32 weights, CFG vs distilled) and sequence parallelism, which is unsupported for the family.

| Model | Hugging Face model ID | Notes |
| --- | --- | --- |
| HiDream-O1-Image | `HiDream-ai/HiDream-O1-Image` | Reference recipe; T2I + TI2I; bf16 |
| HiDream-O1-Image-Dev | `HiDream-ai/HiDream-O1-Image-Dev` | Distilled; fixed 28 steps; TI2I editing |
| HiDream-O1-Image-Dev-2604 | `HiDream-ai/HiDream-O1-Image-Dev-2604` | Same recipe as Dev (earlier snapshot) |

The two Dev checkpoints are guidance-distilled: `--guidance-scale` defaults to 0.0 (no CFG branch, one forward pass per step) and `--num-inference-steps` is ignored in favor of the fixed official 28-step schedule.

## 3. Generate an image

One-shot generation from the CLI:

```bash Command
sglang generate \
  --model-path HiDream-ai/HiDream-O1-Image \
  --prompt "A cat is sitting next to a sign that says 'HiDream-O1'" \
  --num-inference-steps 50 \
  --guidance-scale 5.0 \
  --save-output
```

Or through the OpenAI-compatible image generation API once the server is up:

```python Python
import base64
from openai import OpenAI

client = OpenAI(api_key="EMPTY", base_url="http://127.0.0.1:30010/v1")

response = client.images.generate(
    model="HiDream-ai/HiDream-O1-Image",
    prompt="A cinematic photo of a quiet lakeside cabin at sunrise",
    n=1,
    response_format="b64_json",
)

image_bytes = base64.b64decode(response.data[0].b64_json)
with open("hidream_o1.png", "wb") as f:
    f.write(image_bytes)
```

### Edit an image (TI2I)

Requests that carry a reference image run TI2I editing on every checkpoint (the official repo recommends the full model for editing). One-shot from the CLI:

```bash Command
sglang generate \
  --model-path HiDream-ai/HiDream-O1-Image-Dev \
  --prompt "Turn the sign into glowing neon lettering" \
  --image-path reference.png \
  --save-output
```

A single-reference request inherits the reference's aspect ratio (resized to 2048 on its long side, patch-aligned) unless both `width` and `height` are set. Prompt enhancement (`--pe-server-url`) applies to text-to-image only; editing requests use the raw prompt.

## 4. Configuration tips

- The weight dtype is fixed by the checkpoint: bf16 for the full model, fp32 forwarded under bf16 autocast for Dev. Weight and quantization overrides are rejected rather than silently downcast.
- The trained resolutions are 2048x2048, 2304x1728, 2560x1440, 2496x1664, 3104x1312, 2304x1792 and their transposes. Requests snap to the closest trained resolution by aspect ratio — pixel patches carry no scale invariance, and off-grid sizes degrade quality badly (a single-reference TI2I request keeps the reference aspect instead).
- Sequence parallelism is unsupported: the prompt span is causal while the image span is bidirectional, which needs a dense `[B, 1, S, S]` mask that cannot be sharded along the sequence. Use `--tp-size` for multi-GPU instead. `--cfg-parallel-size 2` is accepted at the default `--guidance-scale 5.0`, since it splits the two CFG branches across GPUs, but it has not been verified end to end.
- Encoder/denoiser/decoder disaggregation does not apply — one component does all three, so the pipeline only runs in the monolithic role.
- The defaults are the reference `full` recipe: 50 steps, `--guidance-scale 5.0`, shift 3.0 (fixed). Classifier-free guidance costs a second forward pass per step, so `--guidance-scale 1.0` halves the step cost at some quality loss.
- Noise is drawn on the host, so a given `--seed` reproduces the same image on any accelerator.
- Prompt enhancement is supported for text-to-image: point `--pe-server-url` at an enhancement server and prompts are rewritten before generation. It is not used for TI2I editing.
- Cache-DiT acceleration is available: start the server with `SGLANG_CACHE_DIT_ENABLED=true`.
