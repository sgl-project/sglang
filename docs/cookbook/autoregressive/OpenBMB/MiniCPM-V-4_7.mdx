## 1. Model Introduction

MiniCPM-V 4.7 is OpenBMB's next MiniCPM-V vision-language model. It pairs a Qwen3.5-style hybrid language backbone — Gated DeltaNet linear-attention layers interleaved with full-attention layers — with a vision encoder that slices high-resolution images into tiles and places image tokens with a canvas M-RoPE layout. It comes in a 1B dense size and a 35B-A3B Mixture-of-Experts size, and thinks by default.

## 2. Configuration Tips

- Every variant needs `--trust-remote-code` and `--mamba-radix-cache-strategy extra_buffer`; both are in every generated command.
- The 1B model runs on one GPU. The 35B-A3B BF16 and FP8 checkpoints use `--tp 2`.
- Serve INT4 at `--tp 1`. The vision tower stays unquantized BF16, and the W4A16 group-128 layout does not divide evenly across the vision layers at TP=2.
- SGLang detects FP8 and INT4 from the checkpoint's `quantization_config`; no `--quantization` flag is needed.
- The **DSPARK** row adds `--speculative-algorithm DSPARK` and `--speculative-draft-model-path` pointing at the variant's DSpark checkpoint. Measured accept length is about 1.3 on 1B, 1.1–1.3 on 35B-A3B BF16, 1.1–1.2 on FP8, and 1.2–1.7 on INT4.
- Thinking is on by default. Without a reasoning parser, the thinking trace stays in `message.content`. To return it in `message.reasoning_content`, add `--reasoning-parser qwen3` (toggle **Reasoning Parser** in the **Parsers** card of the [Playground](#playground)).
- Image and video requests need no extra server flags.

<Warning>
  The FP8 and INT4 checkpoints' remote code fails to import on transformers 5.16 and later. `video_processing_minicpmv4_7.py` imports `BASE_VIDEO_PROCESSOR_DOCSTRING` from `transformers.video_processing_utils`. That code targets transformers 5.12 and earlier; the constant is gone from 5.16 onward, so upgrading transformers does not fix the import. In your local copy of the checkpoint, drop the name from that import and define it in the file instead:

  ```python Example
  from transformers.video_processing_utils import BaseVideoProcessor
  BASE_VIDEO_PROCESSOR_DOCSTRING = ""
  ```

  The BF16 checkpoints are not affected.
</Warning>

## 3. Advanced Usage

### 3.1 Per-request image processing

OpenAI-compatible `/v1/chat/completions` and `/v1/completions` requests accept `mm_processor_kwargs`, which overrides the image processor for that request only:

- `downsample_mode`: `"16x"` (default) or `"4x"`. `"4x"` keeps more visual tokens per tile.
- `max_slice_nums`: the maximum number of high-resolution slices. `1` sends the image without slicing.

<Accordion title="Image token budget (Python)">

```python Example
from openai import OpenAI

client = OpenAI(base_url="http://localhost:30000/v1", api_key="EMPTY")

IMAGE_URL = "https://www.ilankelman.org/stopsigns/australia.jpg"

for overrides in ({}, {"downsample_mode": "4x"}, {"max_slice_nums": 1}):
    resp = client.chat.completions.create(
        model="openbmb/MiniCPM-V-4.7-35B-A3B",
        messages=[{
            "role": "user",
            "content": [
                {"type": "image_url", "image_url": {"url": IMAGE_URL}},
                {"type": "text", "text": "Describe this image in one sentence."},
            ],
        }],
        extra_body={"mm_processor_kwargs": overrides} if overrides else None,
    )
    print(overrides or "default", "prompt_tokens =", resp.usage.prompt_tokens)
```

</Accordion>
