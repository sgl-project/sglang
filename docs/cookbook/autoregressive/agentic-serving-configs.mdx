Use these configurations as starting points for long-context, prefix-reusing
agentic workloads on NVIDIA GPUs. They cover GLM, Inkling, and DeepSeek models,
with hardware-specific memory, attention, caching, and speculative-decoding
settings. The tuning history records earlier measured settings.

<Note>
The [campaign evidence](/cookbook/autoregressive/agentic-serving-evidence) records
measured launch configurations, immutable runtime identities, performance curves,
and available accuracy gates. Those results belong to the recorded runtime and
checkpoint. Some measurements used custom runtime builds. These public-checkpoint
commands have not been rerun on the upstream revision below and do not change the
deployment matrix's verification status.
</Note>

## Prerequisites and versions

- Use Linux, NVIDIA CUDA, and a single node with the GPU type and count shown in
  each heading. All configurations use pipeline parallelism 1.
- Follow [Install SGLang](/docs/get-started/install) for the CUDA build and
  dependencies appropriate to your hardware. Argument names below target
  upstream [`f3f23d128cd5`](https://github.com/sgl-project/sglang/tree/f3f23d128cd576352492334534be7e20fdd8fab6).
  Use that revision when reviewing the commands; changing the runtime requires
  rechecking the configuration. Do not assume a stock image with the same
  version number contains every custom-runtime fix.
- Download the named Hugging Face checkpoint, or replace `--model-path` with its
  local directory. Supply `HF_TOKEN` if its access policy requires it. Pin a
  checkpoint revision for your own comparison. Public checkpoint names do not
  establish identical weight bytes to the artifacts used in the recorded runs.
- Reserve host memory for HiCache in addition to loading buffers and the OS.
  Explicit `--hicache-size` values are per tensor-parallel rank: GLM-5.2 uses
  640 GB across eight H200s or 512 GB across four B200s; GLM-5.3-Flash uses
  400 GB across four GB200s. Check the actual allocation before applying load.

## GLM-5.2

See the [GLM-5.2 cookbook](/cookbook/autoregressive/GLM/GLM-5.2) for model usage.
These commands preserve the HiCache configurations tested with SGLang 0.5.20.
Campaigns using SGLang 0.5.21 did not establish a qualified candidate gain:
parser-preserving runs produced shortened outputs, with the `glm47` grammar
path a candidate cause. Check returned token counts and structured tool calls
before comparing performance.

### H200 TP8 FP8

Checkpoint: [zai-org/GLM-5.2-FP8](https://huggingface.co/zai-org/GLM-5.2-FP8).
The context cap is 250,000 tokens, with five EAGLE steps and six draft tokens.

<Accordion title="Launch GLM-5.2 on H200 TP8">

```bash Launch command
NCCL_NET_GDR_LEVEL=LOC \
sglang serve \
  --model-path zai-org/GLM-5.2-FP8 \
  --tp-size 8 \
  --quantization fp8 \
  --mem-fraction-static 0.92 \
  --context-length 250000 \
  --attention-backend dsa \
  --cp-strategy interleave \
  --dsa-prefill-backend flashmla_kv \
  --enable-hierarchical-cache \
  --enable-prefill-cp \
  --flashinfer-allreduce-fusion-backend auto \
  --fp8-gemm-backend flashinfer_deepgemm \
  --hicache-size 80 \
  --kv-cache-dtype fp8_e4m3 \
  --model-loader-extra-config '{"enable_multithread_load":true,"num_threads":32}' \
  --moe-a2a-backend none \
  --reasoning-parser glm45 \
  --speculative-algorithm EAGLE \
  --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 6 \
  --speculative-num-steps 5 \
  --tool-call-parser glm47 \
  --trust-remote-code \
  --watchdog-timeout 3600
```

</Accordion>

## Inkling

Checkpoint: [thinkingmachines/Inkling-NVFP4](https://huggingface.co/thinkingmachines/Inkling-NVFP4).
See the [Inkling cookbook](/cookbook/autoregressive/ThinkingMachines/Inkling)
for access, multimodal inputs, and model-specific installation guidance.

Both recipes use eight EAGLE steps, nine draft tokens, multi-layer EAGLE, and
rejection sampling. The commands include the multimodal and parser arguments
used by the serving worker, in addition to the engine profile itself.

<Note>
Stock SGLang 0.5.21 startup failed in the recorded comparison on both GPUs
(a missing MoE scale attribute on B200 and a CUDA-graph replay mode error on
H200). The custom-runtime runs therefore do not validate these commands on that
stock image. Recheck startup on the upstream revision you install.
</Note>

### B200 TP8 NVFP4

The configuration tested with SGLang 0.5.21 raises the static memory fraction from 0.65 to 0.80 and
caps running requests at 24. It trades more queueing for the selected
throughput point; it is not a low-TTFT recommendation.

<Accordion title="Launch Inkling on B200 TP8">

```bash Launch command
sglang serve \
  --model-path thinkingmachines/Inkling-NVFP4 \
  --tp-size 8 \
  --quantization modelopt_fp4 \
  --mem-fraction-static 0.8 \
  --context-length 1048576 \
  --max-running-requests 24 \
  --attention-backend fa4 \
  --enable-multi-layer-eagle \
  --enable-multimodal \
  --enable-torch-symm-mem \
  --fp4-gemm-backend flashinfer_trtllm \
  --mamba-full-memory-ratio 0.1 \
  --mamba-radix-cache-strategy extra_buffer \
  --moe-runner-backend flashinfer_trtllm_routed \
  --page-size 128 \
  --reasoning-parser inkling \
  --speculative-algorithm EAGLE \
  --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 9 \
  --speculative-num-steps 8 \
  --speculative-use-rejection-sampling \
  --swa-full-tokens-ratio 0.1 \
  --tool-call-parser inkling \
  --trust-remote-code
```

</Accordion>

## DeepSeek-V4-Flash-0731

See the [DeepSeek-V4 cookbook](/cookbook/autoregressive/DeepSeek/DeepSeek-V4)
for checkpoint variants and DSpark setup. These are the **0731** checkpoints.
Both configurations use DSpark block size 5 and cap running requests at 64.

### B200 TP4 NVFP4

Checkpoint: [nvidia/DeepSeek-V4-Flash-0731-NVFP4](https://huggingface.co/nvidia/DeepSeek-V4-Flash-0731-NVFP4).
The configuration tested with SGLang 0.5.21 changes the prefill/decode interval from 16 to 8.

<Accordion title="Launch DeepSeek-V4-Flash-0731 on B200 TP4">

```bash Launch command
NCCL_NET_GDR_LEVEL=LOC \
sglang serve \
  --model-path nvidia/DeepSeek-V4-Flash-0731-NVFP4 \
  --tp-size 4 \
  --mem-fraction-static 0.88 \
  --context-length 1048576 \
  --max-running-requests 64 \
  --cuda-graph-backend-prefill breakable \
  --cuda-graph-max-bs-prefill 512 \
  --disable-flashinfer-autotune \
  --log-level info \
  --log-level-http info \
  --moe-runner-backend flashinfer_trtllm_routed \
  --prefill-decode-interval 8 \
  --reasoning-parser deepseek-v4 \
  --speculative-algorithm DSPARK \
  --speculative-dspark-block-size 5 \
  --swa-full-tokens-ratio 0.1 \
  --tool-call-parser deepseekv4
```

</Accordion>

### H200 TP4 FP8 with MXFP4 experts

Checkpoint: [deepseek-ai/DeepSeek-V4-Flash-0731](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731).
Keep its MXFP4 expert layout; do not substitute an all-FP8 checkpoint.
The configuration tested with SGLang 0.5.21 adds the 16,384-token prefill chunk, interval 8, and FP8
compute mode for the FlashInfer MXFP4 MoE runner. This mode requires
**FlashInfer 0.6.18 or newer** on H200, as documented in the
[upstream option declaration](https://github.com/sgl-project/sglang/blob/f3f23d128cd576352492334534be7e20fdd8fab6/python/sglang/srt/arg_groups/fields/exec_.py#L895-L901).
Its selected custom-runtime point
had substantially higher TTFT than the incumbent, so measure queueing latency
as well as inter-token latency.

<Accordion title="Launch DeepSeek-V4-Flash-0731 on H200 TP4">

```bash Launch command
NCCL_NET_GDR_LEVEL=LOC \
sglang serve \
  --model-path deepseek-ai/DeepSeek-V4-Flash-0731 \
  --tp-size 4 \
  --mem-fraction-static 0.88 \
  --context-length 1048576 \
  --max-running-requests 64 \
  --chunked-prefill-size 16384 \
  --flashinfer-mxfp4-moe-precision fp8 \
  --moe-runner-backend flashinfer_mxfp4 \
  --prefill-decode-interval 8 \
  --reasoning-parser deepseek-v4 \
  --schedule-policy lof \
  --speculative-algorithm DSPARK \
  --speculative-dspark-block-size 5 \
  --tool-call-parser deepseekv4
```

</Accordion>

### GB200 TP4 NVFP4

## Interpret the tuning evidence

Read the [campaign results and reproduction contract](/cookbook/autoregressive/agentic-serving-evidence)
for per-configuration measurements, source checksums, exact image identities,
and the distinction between measured configurations and these public-checkpoint commands.

Most campaigns used multi-turn, prefix-sharing agentic traffic near 64K input
tokens and 400 output tokens. DeepSeek Pro also used a distinct longer trace.
The optimization objective emphasized output tokens/s/GPU under a mean
inter-token latency limit, not a universal TTFT or tail-latency target.

Several comparisons used simulated speculative acceptance, incomplete output
lengths, different best-feasible concurrency points, or retained measurements.
Those comparisons are not natural-acceptance speedup claims for these public
commands. Benchmark simulation variables are deliberately absent. No
percentage speedup or accuracy qualification transfers with the configuration.

For your own comparison, keep the model revision, image, workload, output
lengths, cache warmup, and client concurrency fixed. Verify complete responses
and tool calls first, then report output throughput alongside TTFT, inter-token
latency, errors, and natural speculative acceptance. Client concurrency and
`--max-running-requests` are different limits: requests above the running cap
can queue.

The generated deployment panels on the model pages retain their existing
verification status.
