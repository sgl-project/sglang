## 1. Model introduction

[Ling-3.1-flash](https://huggingface.co/inclusionAI/Ling-3.1-flash) is a hybrid-attention Mixture-of-Experts language model using the `BailingMoeV3ForCausalLM` architecture. Its 72 layers combine Kimi Delta Attention (KDA) with Multi-head Latent Attention (MLA), with 512 routed experts. The checkpoint uses FP8 E4M3 weights in 128×128 blocks with dynamic activation quantization.

The model supports reasoning and structured tool calling. Its configured context limit is 262,144 tokens (256K); full-length serving remains unverified for Ling-3.1-flash.

**Checkpoint:** [inclusionAI/Ling-3.1-flash](https://huggingface.co/inclusionAI/Ling-3.1-flash). **License:** MIT.

### Verification status

Accuracy uses the full 1,319-question GSM8K set. Stop rate is reported separately from accuracy.

## 2. Configuration tips

- Use eight H200 GPUs with `--tp 8 --ep-size 8`, or four GB300 GPUs with `--tp 4 --ep-size 4`. SGLang detects FP8 from the checkpoint.
- On H200, enable `SGLANG_ENABLE_FP8_BLOCK_GEMV=1` and `SGLANG_ENABLE_FUSED_KDA_OUTPUT_QUANT=1`. Both are included in the generated commands; they are no-ops on GB300 (SM10x).
- Leave `--mem-fraction-static` at its default. SGLang auto-selects the `ling3` reasoning and tool-call parsers for this architecture; you can change the parser settings in the Playground.
- **NEXTN:** the launch recipes pin evaluated revision `b426279f1833b8e097c7c3781d1efa08aba19309` and include `--speculative-algorithm NEXTN`. This revision excludes the BF16 `model.layers.72.eh_proj` from quantization. Verify this exclusion when using a local checkpoint. Measured acceptance length is 2.61 on random tokens and 2.13 on real-text probes.
- **DSpark:** the [Ling-3.0-flash draft](https://huggingface.co/inclusionAI/Ling-3.0-flash-dspark) targets a 2,560-wide, 42-layer model. Ling-3.1-flash uses width 4,096 and 72 layers, so that draft is incompatible. Wait for a 3.1-compatible draft.
- For prefix-heavy, multi-turn workloads, select **Cache fork and tail** in the Playground. It combines `--mamba-radix-cache-strategy extra_buffer`, `--chunked-prefill-size 4096`, and `SGLANG_SPLIT_PREFILL_AT_MAMBA_FORK=1`. GPU checks confirmed both fork and tail states are cached, saving about 576 tokens per subsequent turn in the measured workload.

### Playground support

- **Attention:** BailingKDA shards its projections on attention TP, so DP-attention is available as an unverified override. Its size must divide TP. Prefill CP is disabled because BailingKDA does not implement the required sequence gather and recurrent-state handling.
- **MoE:** Auto, DeepGEMM, and Triton use the FP8 MoE runner paths. Explicit backend and EP overrides are unverified combinations; EP must divide TP.
- **PD disaggregation:** the Playground exposes separate prefill and decode roles with Mooncake transfer. The runtime has hybrid recurrent-state transfer support, but this model's PD deployment has not been verified. Provision separate workers and route requests through a PD-aware gateway; select the role-specific command for each worker.
- **HiCache:** enabling Mooncake on the H200 base preserves NEXTN and adds direct page-first I/O, hybrid-KDA prefix settings, and TCP storage endpoints. Its Playground badge remains unverified until the exact combination is measured.

### Performance

At evaluated revision `b426279f1833b8e097c7c3781d1efa08aba19309`, H200 TP8 + EP8 with NEXTN and the decode gates enabled measured **251.2 output tokens/s** at batch size 1, with mean acceptance length **2.61** on the random-token benchmark. Real-text probes measured acceptance length **2.13**. GB300 NEXTN batch-size-1 result: `{{GB300_NEXTN_BS1}}`.

The image includes KDA normalization/quantization fusion, FP8 block GEMV, router-gate matrix-vector kernels, and a 512-expert top-k router.

## 3. Advanced usage

### 3.1 Reasoning

The `ling3` parser returns reasoning in `message.reasoning_content` and the final answer in `message.content`. Thinking is enabled by default. To request a direct answer, pass `"chat_template_kwargs": {"enable_thinking": false}` in the request body, or `extra_body={"chat_template_kwargs": {"enable_thinking": False}}` with the OpenAI Python client.

<Accordion title="Thinking-on request (Python)">

```python Python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:30000/v1", api_key="EMPTY")

response = client.chat.completions.create(
    model="Ling-3.1-flash",
    messages=[{"role": "user", "content": "What is 15% of 240?"}],
)
print(response.choices[0].message.reasoning_content)
print(response.choices[0].message.content)
```

</Accordion>

### 3.2 Tool calling

The `ling3` tool-call parser returns structured calls in `message.tool_calls`, with `finish_reason` set to `tool_calls`. Send tools through the OpenAI-compatible `tools` field and return each tool result with its matching `tool_call_id`. Read both `reasoning_content` and `content` on the follow-up assistant turn.

<Accordion title="Tool-calling request and follow-up (Python)">

```python Python
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a city",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "City name, e.g. Beijing"},
                    "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]},
                },
                "required": ["city"],
            },
        },
    }
]

response = client.chat.completions.create(
    model="Ling-3.1-flash",
    messages=[{"role": "user", "content": "What's the weather like in Hangzhou right now?"}],
    tools=tools,
    tool_choice="required",
)
call = response.choices[0].message.tool_calls[0]
print(call.function.name, call.function.arguments)
# Then call get_weather yourself and send the result back
# with {"role": "tool", "tool_call_id": call.id, "content": ...}
```

</Accordion>

### 3.3 HiCache with Mooncake

The H200 HiCache combination is verified on the current checkpoint revision with NEXTN: GSM8K smoke 98/100 with stop rate 100%, acceptance length 2.29, and L3 prefetch hits on all 8 TP ranks. Mooncake runs as L3 prefix storage over TCP; start the metadata server, master, and storage client before launching SGLang. Run these services on the same host as the SGLang container:

<Accordion title="Start Mooncake services">

```bash Command
docker run --rm --network host --ipc=host \
  lmsysorg/sglang:dev-ling-3.1-flash \
  bash -lc '
    python3 -m mooncake.http_metadata_server --port 8290 &
    mooncake_master --port 50171 --metrics_port 9024 &
    exec mooncake_client \
      --host=127.0.0.1 \
      --port=50172 \
      --master_server_address=127.0.0.1:50171 \
      --metadata_server=http://127.0.0.1:8290/metadata \
      --protocol=tcp \
      --device_names= \
      --global_segment_size=4294967296 \
      --enable_http_server=true \
      --http_port=8291
  '
```

</Accordion>

<Accordion title="Example Output">

```text Output

Client HTTP server started on port 8291
Starting real client service on 127.0.0.1:50172
...

[TP1] HiCache prefetch success req=... completed=5952 matched=0 loaded=5952 occupied=0
... (all 8 TP ranks)
```

Select **H200 → Low-Latency** in Deployment, then enable **HiCache → Mooncake** in the Playground. Keep NEXTN inherited from the base. Docker commands use host networking so the SGLang container can reach these localhost services. Change the master and metadata endpoints in the **Env** dialog for a remote store.

The TCP recipe leaves `MOONCAKE_DEVICE` and `--device_names` empty. The generated command includes `extra_buffer`, direct page-first I/O, and `hicache_storage_pass_prefix_keys=true` for hybrid KDA prefix reuse. Check that L3 prefetch completes on every TP rank when validating this combination.

For storage sizing and backend details, see [HiCache best practices](/docs/advanced_features/hicache_best_practices).
