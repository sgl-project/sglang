## 1. Model Introduction

**PPLX-Decider-v1.3-27B** is Perplexity's multimodal decision model, fine-tuned from [Qwen3.8-27B](/cookbook/autoregressive/Qwen/Qwen3.8-27B) under the Apache-2.0 license. It returns probability distributions for `choice`, `noul` (yes or no), and `score` questions over one text or multimodal state. It does not generate an answer.

The v1.3 checkpoint changes the serving protocol as well as the weights:

- `decision_config.json` uses format version 2 and declares `attention_mode: noncausal_full_attention` plus `pooling: last`.
- `joint_config.json` declares protocol version 4, template `joint-chunked-readout-v1`, marker `<|fim_suffix|>`, and separator `<|fim_middle|>`.
- The state ends with the separator. Each question is a separate chunk followed by its readout marker, and SGLang scores the answer-code tokens at that marker.
- The 16 full-attention layers read the whole sequence; the 48 Gated DeltaNet layers stay causal.

The checkpoint ships a `Qwen3_5Model` backbone, `readout.safetensors` with 255 rows, and the decision and protocol JSON files. SGLang serves it as `Qwen3_5ForConditionalGeneration` and places the readout in the language-model-head rows of the checkpoint's answer-code token ids.

## 2. Configuration Tips

- **Route.** Use `/v1/systemone`. `/v1/decisions` refuses decision checkpoints because it does not render their trained prompt or readout protocol.
- **Authentication.** The official checkpoint repository may require a Hugging Face token with access. Pass it through the Docker environment or log in before downloading.
- **Images.** Send images in `images` as base64 bytes, a data URL, or an HTTP(S) URL. They precede the state in every question.
- **Noncausal attention is automatic.** SGLang recognizes `attention_mode: noncausal_full_attention` and runs the full-attention layers as encoder layers. It also disables the radix cache and chunked prefill. Do not add those flags manually.
- **One prompt per question.** SGLang uses the checkpoint's evaluated `separate` layout: each question gets its own sequence with the full state. Answers therefore do not depend on which other questions are in the same request.
- **No prefix reuse.** The full-attention outputs depend on the whole prompt, so even repeated identical requests cannot reuse a prefix.
- **Question limit.** There is no separate count limit beyond the context length. The checkpoint's reference implementation was trained on sequences up to 30,720 tokens and does not truncate.
- **Score levels.** The System One API in SGLang accepts up to 10 score levels. The checkpoint readout itself supports more, but this route keeps the published API limit.
- **H20 memory.** On a 96 GB H20, `--mem-fraction-static 0.85` leaves enough room for the noncausal attention workspace. The measured server also auto-selected FA3, Triton GDN kernels, and the Rust tree core, and allocated 253,578 KV tokens plus 95 Mamba state slots.

### Not yet served

- **Locate.** v1.3 ships a `locate-span/` adapter and a `locate` question type in its reference package. SGLang's System One request schema does not expose `locate` questions yet.
- **Isolated multi-question packing.** The checkpoint can place several question blocks after one shared state in its reference `isolated` mode. SGLang currently uses the default `separate` mode, which is the evaluated computation.
- **Fast path.** The reference package's packed CUDA path is not part of the SGLang serving path.

## 4. Request example

```bash Command
curl http://localhost:30000/v1/systemone \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "perplexity-ai/pplx-decider-v1.3",
    "state": "My integration keeps failing with a 401 since we rotated our API key. Please help.",
    "questions": {
      "team": {
        "type": "choice",
        "instructions": "Which team should handle this request?",
        "criteria": {
          "billing": "Charges and refunds",
          "support": "Technical integration errors",
          "sales": "Questions about buying a product"
        }
      },
      "urgent": {
        "type": "noul",
        "instructions": "Is the customer blocked right now?"
      },
      "frustration": {
        "type": "score",
        "criteria": ["calm", "mildly annoyed", "frustrated", "angry"]
      }
    }
  }'
```

The response contains one answer per question id, `usage.input_tokens`, and no generated text.

## 5. Validation status

This support change adds CPU unit coverage for:

- loading `decision_config.json` format version 2 only when its protocol-v4 `joint_config.json` is present and supported;
- forcing the text config noncausal so the full-attention layers use encoder attention;
- rendering the separator, question chunk, and final `<|fim_suffix|>` marker;
- scoring the answer codes from the marker position and escaping control tokens found in user content.

The H20 run above additionally covers real checkpoint loading, concurrency from 1 to 64, Belebele and WinoGrande accuracy, image input, an 18,585-token prompt, and probability parity against the reference implementation. H200, GB300, tensor parallelism, data-parallel replicas, and deterministic replay across server restarts remain unverified.
