## 1. Model Introduction

**NVIDIA Nemotron 3.5 Lightning** is a 30B-A3B hybrid reasoning LLM that interleaves Mamba sequence-modeling layers with Mixture-of-Experts feed-forward layers and standard self-attention, rather than a uniform "attention + MLP" transformer stack. It ships a post-training-quantized **NVFP4** checkpoint that serves on a **single B200 or H100 80GB** at TP=1, and supports thinking-on / thinking-off modes plus structured tool calling.

The model is published as two checkpoints, plus two standalone speculative draft models:

## 2. Configuration Tips

- **Parser names are backend-specific and not interchangeable.** SGLang uses `--reasoning-parser nemotron_3` and `--tool-call-parser qwen3_coder`. vLLM uses `--reasoning-parser nemotron_v3`, and TensorRT-LLM uses `--reasoning_parser nemotron-v3` — different identifiers for the same logical capability.

- **Reasoning tokens count toward `max_tokens`.** If `content` comes back as `None` with `finish_reason: "length"`, the thinking trace consumed the whole budget before an answer was produced — raise `max_tokens`.

- **Hybrid Mamba memory pool.** This is a Mamba + attention hybrid, so GPU memory is split between the KV cache and the Mamba state pool. If concurrency is clamped lower than expected, or you hit a "not enough space for mamba cache" error, tune `--mamba-full-memory-ratio` (or pin `--max-mamba-cache-size`).

- **Tool calling with reasoning on** requires `"force_nonempty_content": true` inside `chat_template_kwargs`. Without it, the server may not correctly surface both the reasoning trace and the tool-call output in the same response.

- **DSpark requires `SGLANG_RAGGED_VERIFY_MODE=static` in the environment.** Without it, the ragged verification path picks its own mode and `--speculative-dspark-block-size` is not honored. The Deploy panel emits this as an inline environment variable on the DSpark cells.

- **Platform backends differ.** B200 runs flashinfer attention *and* flashinfer Mamba with `--mamba-radix-cache-strategy no_buffer`, stochastic Mamba-cache rounding, and overlap scheduling off; H100 uses the platform-default attention path with `extra_buffer`. Don't cross-apply these — the Deploy panel already picks the right set per platform.

## 3. Advanced Usage

### 3.1 Reasoning

Enable the `nemotron_3` reasoning parser (toggle **Reasoning Parser** in the **Parsers** card of the [Playground above](#playground)) to separate thinking from the final answer. The parser is separate-field: the thinking trace lands in `message.reasoning_content` and the answer in `message.content`.

The model supports two modes — Reasoning ON (default) and Reasoning OFF, toggled with `enable_thinking` in `chat_template_kwargs`.

<Accordion title="Reasoning Example (Python)">

```python Example
from openai import OpenAI

client = OpenAI(base_url="http://localhost:30000/v1", api_key="EMPTY")
MODEL = "nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-NVFP4"

# Reasoning on (default)
resp = client.chat.completions.create(
    model=MODEL,
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Write a haiku about GPUs."},
    ],
    max_tokens=1024,
)
print("Reasoning:", resp.choices[0].message.reasoning_content)
print("Content:", resp.choices[0].message.content)

# Reasoning off
resp = client.chat.completions.create(
    model=MODEL,
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Give me 3 interesting facts about SGLang."},
    ],
    max_tokens=256,
    extra_body={"chat_template_kwargs": {"enable_thinking": False,
                                         "force_nonempty_content": True}},
)
print("Content:", resp.choices[0].message.content)
```

### 3.2 Tool Calling

Enable the `qwen3_coder` tool-call parser (toggle **Tool Call Parser** in the **Parsers** card of the [Playground above](#playground)) to surface structured tool calls via `message.tool_calls`.

<Accordion title="Tool Calling Example (Python)">

```python Example
from openai import OpenAI

client = OpenAI(base_url="http://localhost:30000/v1", api_key="EMPTY")
MODEL = "nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-NVFP4"

TOOLS = [
    {
        "type": "function",
        "function": {
            "name": "calculate_tip",
            "parameters": {
                "type": "object",
                "properties": {
                    "bill_total": {"type": "integer", "description": "The total amount of the bill"},
                    "tip_percentage": {"type": "integer", "description": "The percentage of tip to be applied"},
                },
                "required": ["bill_total", "tip_percentage"],
            },
        },
    }
]

completion = client.chat.completions.create(
    model=MODEL,
    messages=[{"role": "user", "content": "My bill is $50. What will be the amount for 15% tip?"}],
    tools=TOOLS,
    max_tokens=1024,
    extra_body={"chat_template_kwargs": {"enable_thinking": True,
                                         "force_nonempty_content": True}},
)

choice = completion.choices[0]
print("Reasoning:", choice.message.reasoning_content)
print("Content:", choice.message.content)
print("Tool calls:", choice.message.tool_calls)
```

### 3.3 Controlling the Reasoning Budget

To cap how long the model thinks before answering, run the thinking phase with a bounded `max_tokens`, close the trace yourself, then continue the turn through the completions endpoint with the remaining budget.

<Accordion title="Reasoning Budget Example (Python)">

```python Example
from typing import Any, Dict, List

import openai
from transformers import AutoTokenizer

MODEL = "nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-NVFP4"


class ThinkingBudgetClient:
    def __init__(self, base_url: str, api_key: str, tokenizer_name_or_path: str):
        self.tokenizer = AutoTokenizer.from_pretrained(tokenizer_name_or_path)
        self.client = openai.OpenAI(base_url=base_url, api_key=api_key)

    def chat_completion(
        self,
        model: str,
        messages: List[Dict[str, Any]],
        reasoning_budget: int = 512,
        max_tokens: int = 1024,
        **kwargs,
    ) -> Dict[str, Any]:
        assert max_tokens > reasoning_budget, "reasoning_budget must be smaller than max_tokens"

        response = self.client.chat.completions.create(
            model=model, messages=messages, max_tokens=reasoning_budget, **kwargs
        )
        reasoning_content = response.choices[0].message.reasoning_content or ""
        if "</think>" not in reasoning_content:
            reasoning_content = f"{reasoning_content}.\n</think>\n\n"

        reasoning_tokens_used = len(
            self.tokenizer.encode(reasoning_content, add_special_tokens=False)
        )
        remaining_tokens = max_tokens - reasoning_tokens_used
        assert remaining_tokens > 0, "Increase max_tokens or lower reasoning_budget"

        messages.append({"role": "assistant", "content": reasoning_content})
        prompt = self.tokenizer.apply_chat_template(
            messages, tokenize=False, continue_final_message=True
        )
        response = self.client.completions.create(
            model=model, prompt=prompt, max_tokens=remaining_tokens, **kwargs
        )
        return {
            "reasoning_content": reasoning_content.strip().strip("</think>").strip(),
            "content": response.choices[0].text,
            "finish_reason": response.choices[0].finish_reason,
        }


budget_client = ThinkingBudgetClient(
    base_url="http://localhost:30000/v1", api_key="EMPTY", tokenizer_name_or_path=MODEL
)

resp = budget_client.chat_completion(
    model=MODEL,
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Write a haiku about GPUs."},
    ],
    max_tokens=1024,
    reasoning_budget=128,
)
print("Reasoning:", resp["reasoning_content"])
print("Content:", resp["content"])
```

**MTP** (Multi-Token Prediction) uses a small draft layer built into the model to guess several tokens ahead, which the model then verifies in one step. SGLang reaches that layer through its EAGLE path, so `--speculative-draft-model-path` points at the target checkpoint itself.

**DFlash** does the same thing, but the guesses come from a separate draft model rather than a layer inside the model.

**DSpark** also uses a separate draft model, but it proposes a whole block of tokens at once rather than one at a time. It requires `SGLANG_RAGGED_VERIFY_MODE=static` in the environment. The public draft checkpoint uses `sample_from_anchor=false` and works with static ragged verification without SPS or STS calibration tables.

<Note>
Measure acceptance length with **representative text prompts** at temperature 1. Random token IDs are useful for fixed-shape throughput measurements, but are not a valid stochastic draft-quality workload — they will understate acceptance for all three decoders.
</Note>
