This evidence accompanies the [agentic serving configurations](/cookbook/autoregressive/agentic-serving-configs).
It records the measured configuration and its limits for each model, GPU, and recorded SGLang version.
The tables use **output tokens/s/GPU** and **mean** inter-token latency (ITL) and
time to first token (TTFT). They are not the total-input-plus-output throughput or
P50 latency used by the deployment cards, so these results stay outside that matrix.

<Note>
These are existing campaign measurements, not new runs of the public launch commands.
Most selected configurations ran inside custom runtime builds. The GLM-5.3 performance
arms ran on a public SGLang image, with the tool parser omitted. Private image digests
and trace hashes identify the evidence but do not provide public access to those assets.
The ports on the companion page still need testing with their public checkpoint and runtime.
</Note>

configured-only variants are included without implying a new measured improvement.

DeepSeek 0.5.20 measurements pin context to 262,144 tokens. The ports and recorded
0.5.21 workers use 1,048,576; the earlier results do not validate the larger window.
Public checkpoint revision SHAs are retained in the catalog. Custom checkpoint aliases
are omitted and fingerprinted; their byte equivalence to a public Hugging Face revision
is not established.

## Historical measurements

Each row below aggregates the retained measurements at one configuration and client
concurrency. The objective was output throughput under mean ITL ≤ 20 ms. All repeats
are included, including repeats that exceed that bound; no favorable replicate is selected.
The `±` value is the sample standard deviation of throughput, and `n` is the number
of retained measurements. A single measurement has no estimated standard deviation.
TTFT values are means, not tail latencies.

The 0.5.18 groups include the original measurement and two later repeats with matching
configuration, server image, checkpoint, and workload. Their client image digests differ,
although the recorded client versions and replay protocol match; the catalog preserves
those identities and the CSV preserves each run. GLM-5.3 B200 optimized groups include the identical first confirmation
labeled `prior` in the source CSV. Its TP8 generic group has only two retained repeats.

## SGLang 0.5.21 measurements

All 42 points below use **synthetic speculative acceptance**, with the imposed acceptance
length (AL) shown per table. They describe performance under that benchmark assumption,
not natural speculative acceptance or semantic accuracy. Each point is one measurement.
The public launch commands deliberately omit those simulation overrides.

The retained request-receipt checksums matched local evidence for 35 points. The seven
DeepSeek Flash B200 receipts were referenced but not present in the checked-in evidence;
their CSV qualification status is preserved without claiming those receipts were rechecked.

Client concurrency can exceed `max-running-requests`; queued requests explain why
throughput may flatten while TTFT rises. These are supporting tables, not a claim that
every point meets the latency target or that every high-concurrency point is steady state.

## Reproduction protocol and identities

The historical 4% workload replays 942 Mooncake trace records in sequential order,
with synthetic text reconstructed from hashes and lengths, `ignore_eos: true`,
`skip_special_tokens: false`, and server token accounting. DeepSeek 0.5.20 filters this
trace to 912 records whose input plus output lengths fit 262,144 tokens. The 0.5.21
DeepSeek Pro tables instead use the 3,541-record legacy 15% trace. These populations
must not be pooled into a runtime-version speed comparison.

The source rows record SGLang 0.5.18, 0.5.20, or 0.5.21, and AIPerf client identity
where available. The catalog preserves recorded image digests, public checkpoint revision SHAs,
client options, warmup policies or adaptation hashes, and workload hashes. Null means
the source did not retain that field or an adjacent omission marker explains why
it is withheld. Custom runtimes remain explicitly distinguished from public images.

The public GLM-5.3 performance image is `docker.io/lmsysorg/sglang@sha256:06e4f2ed21afde4ff513cda65070124e727ba23ccaeff7712b8c40e1097d611f`
(SGLang 0.5.20, source `94602c9c2b7cbdb8efd5c52802dac6a1c180089e`).
The other public image entries identify comparison arms. Tuned configurations measured
on custom runtimes retain that distinction.
Source paths, custom checkpoint aliases, private registry addresses, and trial
infrastructure are omitted. Recorded SGLang versions group the evidence; they do not
establish that a custom build is equivalent to the corresponding upstream release.

For a new public-runtime comparison, preserve the checkpoint, effective arguments,
trace population, client concurrency, output lengths, and cache state. Record natural
acceptance separately from simulations. A matching trace hash verifies identity only
when the original bytes are available; it does not supply the trace. The evidence below
supports auditing the recorded results, not claiming a fresh public-runtime reproduction.
