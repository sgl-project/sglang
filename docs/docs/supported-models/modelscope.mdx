---
title: "Use Models From ModelScope"
---
To use a model from [ModelScope](https://www.modelscope.cn), set the environment variable `SGLANG_USE_MODELSCOPE`.

```bash Set Environment Variable
export SGLANG_USE_MODELSCOPE=true
```

We take [Qwen2-7B-Instruct](https://www.modelscope.cn/models/qwen/qwen2-7b-instruct) as an example.

Launch the Server:
```bash Python
python -m sglang.launch_server --model-path qwen/Qwen2-7B-Instruct --port 30000
```

Or start it by docker:

```bash Docker
docker run --gpus all \
    -p 30000:30000 \
    -v ~/.cache/modelscope:/root/.cache/modelscope \
    --env "SGLANG_USE_MODELSCOPE=true" \
    --ipc=host \
    lmsysorg/sglang:latest \
    python3 -m sglang.launch_server --model-path Qwen/Qwen2.5-7B-Instruct --host 0.0.0.0 --port 30000
```

Note that modelscope uses a different cache directory than huggingface. You may need to set it manually to avoid running out of disk space.

## Select a source for each model

You can use `hf://owner/repo` or `modelscope://owner/repo` with
`--model-path`, `--tokenizer-path`, and `--speculative-draft-model-path`.
Each prefix selects that repository's source independently of
`SGLANG_USE_MODELSCOPE`, so the target and draft can come from different Hubs:

```bash
sglang serve \
    --model-path modelscope://LLM-Research/Meta-Llama-3.1-8B-Instruct \
    --speculative-algorithm EAGLE3 \
    --speculative-draft-model-path hf://lmsys/sglang-EAGLE3-LLaMA3.1-Instruct-8B
```

Use the repository ID published by the selected Hub; the same weights can have
different IDs on Hugging Face and ModelScope.

The prefixes also work with `python -m sglang.launch_server` and Python `Engine`
arguments. Omitted tokenizers use the target checkpoint; the default served
model name is the target's `owner/repo`.

Only repository roots are supported. Select versions with `--revision` or
`--speculative-draft-model-revision`, not within the prefixed path. Each SDK
handles authentication and caching (`--download-dir`); failed downloads do not
switch Hubs. ModelScope sources require the `modelscope` package.

Downloads select the requested weight format (`auto` prefers safetensors),
without fetching alternate formats. Tokenizer-only and `dummy` loads fetch
metadata only. Other supported load formats are `safetensors`, `fastsafetensors`,
`instanttensor`, `pt`, `npcache`, and `mistral`; use a local snapshot for other loaders.
With `--trust-remote-code`, cross-repository `auto_map` code uses the same Hub as
its model or tokenizer, without modifying the cached repository files.

Unprefixed IDs, local paths, and existing remote-storage URLs are unchanged.
