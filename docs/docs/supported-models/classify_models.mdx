This document describes SGLang's `/v1/classify` endpoint for sequence and token classification.

## Overview

Classify text with a supported model and get scores for every class. The shape of `label` depends on whether the model predicts one or multiple classes and whether it classifies the whole input or each token.

### Multi-label classification

If your checkpoint's `config.json` declares `"problem_type": "multi_label_classification"`, `/v1/classify` applies an elementwise sigmoid to its logits. Each entry in `probs` is an independent class probability, so the entries do not need to sum to one. For example, logits `[2.0, 2.0]` produce probabilities of approximately `[0.880797, 0.880797]`.

For a multi-label sequence classifier, `label` is an array of classes whose score is at least the request's `threshold`, in class ID order. The threshold defaults to `0.5`. For example, scores of `0.92` for `billing` and `0.88` for `urgent` return `"label": ["billing", "urgent"]` at the default threshold. If no score meets the threshold, `label` is an empty array. If your client served a multi-label checkpoint before this change, update it to accept an array in `label`.

For `single_label_classification` or an unset `problem_type`, the endpoint applies softmax. If a supported checkpoint explicitly declares `"problem_type": "regression"`, `probs` contains the raw regression scores. These scores may fall outside the range from 0 to 1.

### Token classification

For supported models that return logits for each input token, each result in `data` contains a `probs` matrix with shape `[num_tokens, num_classes]`. Rows follow input token order, including special tokens. `num_classes` counts classes, and `index` identifies the input in the batch. Inputs in the same batch can have different token counts.

For single-label token classification, `label` is an array with the highest-scoring class for each token. For multi-label token classification, `label` contains one array of qualifying classes per token, including an empty array for any token whose scores fall below the threshold. The activation follows the same `problem_type` rule for each token.

Here is an example `data` entry for a multi-label classifier with two input tokens and two classes.

```json
{
  "index": 0,
  "label": [["LABEL_0", "LABEL_1"], []],
  "probs": [[0.880797, 0.817574], [0.119203, 0.182426]],
  "num_classes": 2
}
```

You can provide token IDs through the `input` field when you need to control token positions:

```json
{
  "model": "MODEL_PATH",
  "input": [1, 2]
}
```

Replace `MODEL_PATH` with your served model name. This response format preserves per-token scores; it does not merge tokens into entity spans.

## API Endpoint

```text Output
POST /v1/classify
```

## Request Format

```json Config
{
  "model": "model_name",
  "input": "text to classify"
}
```

### Parameters

- `model` (string, required): The name of the classification model to use
- `input` (string, required): The text to classify
- `user` (string, optional): User identifier for tracking
- `rid` (string, optional): Request ID for tracking
- `priority` (integer, optional): Request priority
- `threshold` (number, optional): Minimum score for a positive label in multi-label classification. Accepts values from `0` to `1`, inclusive. Defaults to `0.5`.

## Response Format

```json Config
{
  "id": "classify-9bf17f2847b046c7b2d5495f4b4f9682",
  "object": "list",
  "created": 1745383213,
  "model": "jason9693/Qwen2.5-1.5B-apeach",
  "data": [
    {
      "index": 0,
      "label": "Default",
      "probs": [0.565970778465271, 0.4340292513370514],
      "num_classes": 2
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "total_tokens": 10,
    "completion_tokens": 0,
    "prompt_tokens_details": null
  }
}
```

### Response Fields

- `id`: Unique identifier for the classification request
- `object`: Always "list"
- `created`: Unix timestamp when the request was created
- `model`: The model used for classification
- `data`: Array of classification results
  - `index`: Index of the result
  - `label`: The highest-scoring class for each prediction position, or all classes at or above the threshold for a multi-label model. Token results contain one entry per token.
  - `probs`: Scores in class ID order. Sequence results return one vector, and token results return one vector per token.
  - `num_classes`: Total number of classes
- `usage`: Token usage information
  - `prompt_tokens`: Number of input tokens
  - `total_tokens`: Total number of tokens
  - `completion_tokens`: Number of completion tokens (always 0 for classification)
  - `prompt_tokens_details`: Additional token details (optional)

## Example Usage

### Using curl

```bash Command
curl -v "http://127.0.0.1:8000/v1/classify" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "jason9693/Qwen2.5-1.5B-apeach",
    "input": "Loved the new café—coffee was great."
  }'
```

### Using Python

```python Example
import requests
import json

# Make classification request
response = requests.post(
    "http://127.0.0.1:8000/v1/classify",
    headers={"Content-Type": "application/json"},
    json={
        "model": "jason9693/Qwen2.5-1.5B-apeach",
        "input": "Loved the new café—coffee was great."
    }
)

# Parse response
result = response.json()
print(json.dumps(result, indent=2))
```

## Supported Models

The classification API works with any classification model supported by SGLang, including:

### Classification Models (Multi-class)
- `LlamaForSequenceClassification` - Multi-class classification
- `Qwen2ForSequenceClassification` - Multi-class classification
- `Qwen3ForSequenceClassification` - Multi-class classification
- `BertForSequenceClassification` - Multi-class classification
- `Gemma2ForSequenceClassification` - Multi-class classification

**Label Mapping**: The API automatically uses the `id2label` mapping from the model's `config.json` file to provide meaningful label names instead of generic class names. If `id2label` is not available, it falls back to `LABEL_0`, `LABEL_1`, etc., or `Class_0`, `Class_1` as a last resort.

### Reward Models (Single score)
- `InternLM2ForRewardModel` - Single reward score
- `Qwen2ForRewardModel` - Single reward score
- `LlamaForSequenceClassificationWithNormal_Weights` - Special reward model

**Note**: The `/classify` endpoint in SGLang was originally designed for reward models but now supports all non-generative models. Use `/v1/classify` for the classification response format described here.

## Error Handling

The API returns appropriate HTTP status codes and error messages:

- `400 Bad Request`: Invalid request format or missing required fields
- `500 Internal Server Error`: Server-side processing error

Error response format:
```json Config
{
  "error": "Error message",
  "type": "error_type",
  "code": 400
}
```

## Implementation Details

The classification API is implemented using:

1. **Python HTTP Server**: Implements the actual endpoint in `python/sglang/srt/entrypoints/http_server.py`
2. **Classification Service**: Handles the classification logic in `python/sglang/srt/entrypoints/openai/serving_classify.py`

## Compatibility

Single-label sequence responses use a string `label`. Clients switching from vLLM or an earlier SGLang release should accept arrays in `label` when serving multi-label or token classifiers.
