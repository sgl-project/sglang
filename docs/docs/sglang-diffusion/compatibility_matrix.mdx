Use the model ID shown below as `--model-path` with `sglang generate` or
`sglang serve`. Python API users can pass the same ID to the model-loading
helpers.

The catalog follows the native model registry. Detector-based families and
local directories may also work when their model metadata matches a supported
pipeline, so the list is intentionally a set of known public entry points rather
than an exhaustive list of every compatible checkpoint.

## Component overrides

Individual pipeline components can be replaced with `--<component>-path`. The
value can be a Hugging Face repo ID or a local component directory. Config files
use the equivalent `component_paths.<component>` mapping.

```bash Command
sglang generate \
  --model-path black-forest-labs/FLUX.2-dev \
  --vae-path black-forest-labs/FLUX.2-small-decoder \
  --transformer-path /models/flux2/transformer
```

```yaml Config
model_path: black-forest-labs/FLUX.2-dev
component_paths:
  vae: black-forest-labs/FLUX.2-small-decoder
  transformer: /models/flux2/transformer
```

Use the component name from `model_index.json` or the native pipeline's
registered module name.

<AccordionGroup>
  <Accordion title="VAE components">
    Use `vae`, `video_vae`, or `audio_vae`. `vae` is the common image-generation
    override; the modality-specific names only apply to pipelines that expose
    separate video or audio VAEs.
  </Accordion>
  <Accordion title="Transformer and DiT components">
    Use `transformer`, `video_dit`, or `audio_dit`. `transformer` is the standard
    main-denoiser override. For pre-quantized weights, see
    [Quantization](./quantization).
  </Accordion>
  <Accordion title="Text encoders and preprocessors">
    Supported keys include `text_encoder`, `text_encoder_2`, `tokenizer`,
    `processor`, and `image_processor`. Replacement encoders often require their
    matching preprocessing assets.
  </Accordion>
  <Accordion title="Auxiliary components">
    Pipeline-specific keys include `scheduler`, `spatial_upsampler`, `vocoder`,
    `connectors`, `dual_tower_bridge`, `image_encoder`, and
    `vision_language_encoder`.
  </Accordion>
</AccordionGroup>

Two concrete VAE overrides used by SGLang Diffusion docs or tests are:

- `black-forest-labs/FLUX.2-small-decoder`: decoder-only FLUX.2 VAE
- `fal/FLUX.2-Tiny-AutoEncoder`: tested compact FLUX.2 VAE

Component overrides are valid only when the selected pipeline exposes that
component. An override does not enable quantization by itself: the checkpoint
must contain metadata for a format supported by its loader. See
[Quantized Component Repositories](./quantization#quantized-component-repositories).
