Spectrum forecasts DiT features and skips selected denoising steps. It is an
approximation: validate visual or video quality and latency on the exact model,
shape, hardware, and sampling settings you plan to deploy.

## Quick start

```bash
sglang generate \
  --model-path Wan-AI/Wan2.1-T2V-1.3B-Diffusers \
  --prompt "A paper boat floating through a misty mountain lake" \
  --enable-spectrum \
  --save-output
```

## Scope and constraints

- Available on native FLUX.1, Wan, HunyuanVideo, SD3, and MiniMax-H3
  implementation paths. It is not a `--backend diffusers` feature and does
  not currently cover FLUX.2.
- The request control is available through `sglang generate` and Python
  sampling parameters. It is not a `sglang serve` or OpenAI-server request
  option yet.
- Spectrum and `--enable-teacache` are mutually exclusive. On MiniMax-H3
  it also cannot run with Cache-DiT / `quality="high"`, or with SP &gt; 1.
- MiniMax-H3 50-step recipe: `--spectrum-warmup-steps 11
  --spectrum-window-size 5 --spectrum-flex-window 1.0`. Defaults are the
  20-step schedule. See the [MiniMax-H3 cookbook](/cookbook/diffusion/MiniMax/MiniMax-H3).
- Start with the defaults. `--debug` adds shadow-prediction validation work,
  so its latency is not representative of normal Spectrum execution.

## Advanced controls

Use `--enable-spectrum` explicitly. Providing any Spectrum override also
enables it, but that implicit behavior is intended for scripts rather than new
commands.

| Flag | Default | Purpose |
| --- | --- | --- |
| `--spectrum-window-size` | `2.0` | Initial step-skipping window |
| `--spectrum-flex-window` | `0.75` | Window growth after a real forward |
| `--spectrum-warmup-steps` | `5` | Initial exact DiT forwards |
| `--spectrum-m` | `4` | Chebyshev basis count |
| `--spectrum-lam` | `0.1` | Ridge regularization |
| `--spectrum-tau-num-steps` | `50` | Chebyshev time horizon |
| `--history-size` | `100` | Recent feature-history capacity |
| `--taylor-order` | `1` | Local predictor order (`1`, `2`, or `3`) |
| `--w` | `1.0` | Chebyshev/Taylor blend weight |

<Warning>
These controls trade speed against output fidelity. Change one control at a
time and retain a lossless baseline for comparison.
</Warning>

## Combining with CFG gating

CFG gating (`--cfg-gate-step F`; `1.0`, the default, turns it off) is a
separate lossy option. After fraction `F` of the steps it skips the
unconditional forward and reuses the conditional-minus-unconditional difference
frozen at that step, so the guidance term stops following the trajectory. Its
error grows with the number of reused steps and with the guidance scale.

With both enabled, every step before the gate runs real forwards on both
branches, so the frozen difference never contains a Spectrum forecast. Spectrum
therefore cannot skip those steps, and the combination is slower than Spectrum
alone without being more accurate. On Wan, use Spectrum alone.

Wan2.1-T2V-1.3B at its defaults (480x832, 81 frames, 50 steps, guidance 3.0),
seed 42, two prompts, one B200, compared with the same request run without
acceleration (latency from single runs, indicative only):

| Setting | Mean frame PSNR | Mean LPIPS | Latency |
| --- | --- | --- | --- |
| None | — | — | 60 s |
| `--enable-spectrum` | 26.8–27.6 dB | 0.08–0.10 | 19 s |
| `--cfg-gate-step 0.3` | 30.1–31.2 dB | 0.02–0.03 | 39 s |
| Both of the above | 28.5–30.3 dB | 0.05–0.06 | 25 s |
| `--cfg-gate-step 0.7` | 40.2–42.1 dB | 0.003–0.005 | 51 s |
| `--cfg-gate-step 0.9` | 46.1–47.1 dB | 0.001 | 57 s |

At guidance 5.0 the accelerated settings lose another 1–7 dB.
