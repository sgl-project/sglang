## Why and What is EPD Disaggregation?

In modern Vision-Language Model (VLM) inference, request execution naturally decomposes into three distinct stages: Encoder, Prefill, and Decode.
The Encoder stage performs vision preprocessing and ViT-based image encoding, which is highly compute-intensive but only required during request initialization. The Prefill stage processes the full multimodal input sequence to initialize the language model’s Key-Value (KV) cache, while the Decode stage is dominated by memory bandwidth and KV cache access for autoregressive token generation.

Existing deployments typically colocate these stages within a unified execution engine, or at best apply Prefill–Decode (PD) disaggregation. However, such designs still tightly couple vision encoding with language prefill, leading to inefficient resource utilization, limited scalability for image-heavy workloads, and suboptimal scheduling under load.

To address these challenges, we introduce Encoder–Prefill–Decode (EPD) Disaggregation in SGLang. EPD further separates vision encoding from language processing, enabling independent horizontal scaling of encoder servers, improved load balancing for multimodal requests, and seamless integration with existing PD disaggregation to form a fully decoupled three-tier inference architecture.

### Usage

You can launch a language-only model using `--language-only`, or an encoder-only model using `--encoder-only`.
For Python language-only workers, configure encoder endpoints with `--encoder-urls` or register them dynamically.

We support multiple encoder transfer backends, including zmq_to_scheduler, zmq_to_tokenizer, and mooncake (the default is zmq_to_scheduler). The backend can be selected using `--encoder-transfer-backend`.

### External encoder selection

An external router such as Dynamo selects E and calls its `Stage` RPC. It
passes the returned descriptor to the selected P/PD in the `encoder_handoff`
field of a tokenized `/generate` request. Enable
`SGLANG_ENABLE_EXTERNAL_ENCODER_HANDOFF=1` on E and every language worker.
Start E with `--encoder-only --grpc-mode`. On the Rust language workers,
use `--language-only` with `SGLANG_RUST_SERVER=1`. The worker
uses the encoder identified by the descriptor, so you can omit `--encoder-urls`.
Use the same `--encoder-transfer-backend nixl` or
`--encoder-transfer-backend zmq_to_scheduler` on E and P/PD. In external
mode, `auto` selects `zmq_to_scheduler` at every TP size. NIXL requires
the UCX plugin on both ends.

For staged `/generate`, pass one `mm_hashes` routing hint per source in
image, video, then audio order, preserving order within each list. A video's
frames share its source hint. Prompt placeholders can interleave the media.

Mount a file containing the same 32 random bytes on E, P/PD and D. Set
`SGLANG_ENCODER_HANDOFF_KEY_FILE` to its path on each worker. Generate it once
per deployment with `(umask 077 && openssl rand 32 > encoder-handoff.key)`.
On each E, set `SGLANG_ENCODER_HANDOFF_ENDPOINT=grpc://host:port` to the
address P/PD can reach when the bind address is a wildcard or differs from
that address. E authenticates its endpoint, process instance, transfer ID and
media layout with HMAC-SHA256. P/PD and D verify the receipt at ingress before
using its metadata or contacting E. E computes a content digest for each staged
embedding from its modality, dtype, shape and tensor bytes. P/PD verifies the
received host tensors on a background thread before making them available to
the scheduler, even when `SGLANG_MM_SKIP_COMPUTE_HASH` is enabled on either
worker. D uses the authenticated digests to reconstruct the
same media identities. Keep the encoder and language listeners
private. Restart the workers with a new shared key to rotate it.

The router owns the receipt until P/PD claims it. It can call `Release` on the
issuing E after cancellation or a definitive routing rejection. E keeps unclaimed
receipts in its native request registry for `SGLANG_ENCODER_SEND_TIMEOUT`
(default 180 seconds) to recover from a lost response or a router crash.
P/PD owns a claimed transfer and its receive buffer. D only uses the layout.

With NIXL, rank 0 of P/PD registers a host-memory pool at startup. Set
`SGLANG_ENCODER_NIXL_POOL_SIZE_MB` to size it (default 256 MiB). Each transfer
uses a slice, which stays reserved until the write is fenced and the last tensor
view is released. Each sender thread on E caches the peer registration across
writes to the same pool. P/PD registers individual buffers when the pool is
disabled, when startup registration fails, or when the embedding does not fit
an available slice. Set the size to `0` to disable pooling.

If a NIXL write's outcome is unknown, P/PD asks the issuing E to confirm the
write has retired. It allows E's advertised send timeout (default 180 seconds)
plus one `SGLANG_ENCODER_GRPC_TIMEOUT_SECS` window (default 60 seconds).
With an older E that omits its send timeout, P/PD uses its local
`SGLANG_ENCODER_SEND_TIMEOUT`. Without a
matching acknowledgement or a native write-completion notification, the memory
stays registered in quarantine. Quarantine permits up to one additional
destination per configured live slot before applying backpressure.

Use PP=DP=1. Each encoder replica can use tensor parallelism within one node.
All media in a request go to one encoder replica. On P/PD, TP rank 0 claims
the transfer once, receives and verifies the embeddings, and broadcasts each
item's tensor to its TP peers. E tracks one destination and can release its
embedding when that send completes. With NIXL, only rank 0 registers a receive
pool. P/PD receives host tensors over NIXL or ZMQ and broadcasts them
through the CPU process group (Gloo). Native scheduler ZMQ can send directly
to each TP rank, which avoids that broadcast and sends one copy from E per rank.

In E/P/D, D reconstructs token positions from the descriptor. Configure P→D KV
transfer independently.

A registered Python multimodal processor declares its `staged_layouts` by
model type. Its `StagedMediaLayout` supplies the media capabilities, embedding
dimensions, and grid or timing rules used on E and P/PD. A processor with the
same metadata requirements can reuse the existing wire format.

Qwen-family image and video handoffs use v1 and v2 respectively. Other model
families use v3 to carry the native model type, tensor width and per-item row
counts, plus the grids, dimensions or timing their processors need.
Requests containing separate audio items use v4. E records the native feature
length, embedding rows, width and identity for each audio input. The transfer
preserves each modality's native width, including when DeepStack vision and
audio share a request. The language
processor uses these lengths to reconstruct audio token spans and positions.
Use the same audio-capable model on both E and P/PD (and D in a split
deployment). Independent audio items may share a prompt with images or videos
when the checkpoint supports those modalities. Video requires a compatible
decoder on E. Embedded soundtracks are outside this protocol.

### Encoder transfer with Mooncake

`--encoder-transfer-backend mooncake` controls **how encoder outputs are transferred** between encoder and language/prefill services. It is an encoder transfer option and can be used independently of the global multimodal embedding cache.

Example:

```bash Command
# encoder
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --encoder-only \
  --encoder-transfer-backend mooncake \
  --port 30000

# language-only server
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --language-only \
  --encoder-urls http://127.0.0.1:30000 \
  --encoder-transfer-backend mooncake \
  --port 30002
```

### Intel XPU

On Intel XPU, the Mooncake encoder transfer runs on Mooncake's TENT engine, which copies the embedding card to card through Level Zero IPC, so no RDMA NIC is needed. This needs a Mooncake transfer engine built with `-DUSE_XPU=ON -DUSE_TENT=ON` (`docker/xpu.Dockerfile` installs one).

Both servers must see both cards: list them in `ZE_AFFINITY_MASK` and pick each server's card with `--base-gpu-id`. A server that sees only its own card cannot map the other card's buffer, and the transfer falls back to TCP.

Inside a container, also run with `--cap-add SYS_PTRACE` (or `--privileged`): TENT maps the peer's buffer through `pidfd_getfd()`, which Docker blocks by default, and without it the copy quietly takes another route. See the [Mooncake backend note for P/D on Intel XPU](/docs/hardware-platforms/xpu#mooncake-backend).

Run each server in its own terminal, and set the `export` line in both: without it, the language server does not use TENT and cannot see the encoder's card.

```bash Command
export MC_USE_TENT=1 ZE_AFFINITY_MASK=0,1 TORCHINDUCTOR_USE_STATIC_CUDA_LAUNCHER=0

# encoder on card 0
python -m sglang.launch_server \
  --model-path Qwen/Qwen2.5-VL-3B-Instruct \
  --device xpu \
  --attention-backend intel_xpu \
  --page-size 64 \
  --encoder-only \
  --encoder-transfer-backend mooncake \
  --base-gpu-id 0 \
  --port 30000

# language-only server on card 1
python -m sglang.launch_server \
  --model-path Qwen/Qwen2.5-VL-3B-Instruct \
  --device xpu \
  --attention-backend intel_xpu \
  --page-size 64 \
  --language-only \
  --encoder-urls http://127.0.0.1:30000 \
  --encoder-transfer-backend mooncake \
  --base-gpu-id 1 \
  --port 30002
```

<Note>
`TORCHINDUCTOR_USE_STATIC_CUDA_LAUNCHER=0` works around an inductor static Triton launcher issue on torch 2.14+xpu that crashes the encoder on its first image. Drop it once your torch build includes the fix (likely pytorch/pytorch#199511).
</Note>

The encoder preprocesses images on CPU by default, while a colocated server runs the image processor on the device, so the two produce slightly different image embeddings. Set `SGLANG_ENCODER_IMAGE_PROCESSOR_USE_GPU=1` on the encoder to preprocess on the device and get the same embeddings as colocated serving.

### Global multimodal embedding cache with Mooncake

SGLang also supports a Mooncake-backed **global multimodal embedding cache** for EPD workloads. When enabled on encoder servers, repeated image inputs can reuse previously computed ViT embeddings across instances instead of running the vision encoder again.

This feature is useful when:

- the deployment serves repeated or overlapping image inputs,
- encoder compute is the bottleneck, and
- Mooncake is already available in the cluster.

At a high level, the encoder checks whether the image embedding already exists in Mooncake. Cache hits are prefetched from the global store, while misses are encoded normally and inserted into the cache in the background.

To enable it:

- install and configure Mooncake in the same way as other SGLang Mooncake integrations,
- add `--enable-mm-global-cache` on the encoder server.

`--enable-mm-global-cache` controls **whether multimodal embeddings are looked up and stored in the global Mooncake cache**. It is separate from `--encoder-transfer-backend`, which only controls encoder output transport.

For Mooncake deployment and configuration details, see [HiCache best practices](./hicache_best_practices#deployment-with-mooncake) and the [Mooncake backend README](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/mem_cache/storage/mooncake_store/README.md).

Example:

```bash Command
# Shared Mooncake configuration
export MOONCAKE_TE_META_DATA_SERVER="http://127.0.0.1:8080/metadata"
export MOONCAKE_MASTER="127.0.0.1:50051"
export MOONCAKE_PROTOCOL="rdma"
export MOONCAKE_GLOBAL_SEGMENT_SIZE="4gb"

# encoder with global multimodal cache enabled
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --encoder-only \
  --enable-mm-global-cache \
  --port 30000

# language-only server
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --language-only \
  --encoder-urls http://127.0.0.1:30000 \
  --port 30002
```

Notes:

- This cache is for **multimodal encoder embeddings**, not the language model KV cache.
- The feature currently uses Mooncake as the shared backing store.
- It can be enabled regardless of which `--encoder-transfer-backend` you use.
- It is most relevant for EPD or encoder-disaggregated VLM deployments where the same images are likely to appear across requests or instances.

- EP Disaggregation

```bash Command
# encoder 0
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --encoder-only \
  --encoder-transfer-backend zmq_to_scheduler \
  --port 30000
# encoder 1
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \

  --port 30001
# language-only server
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --language-only \
  --encoder-urls http://127.0.0.1:30000 http://127.0.0.1:30001 \
  --encoder-transfer-backend zmq_to_scheduler \
  --port 30002
```

- EPD Disaggregation

```bash Command
# encoder 0
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --encoder-only \
  --encoder-transfer-backend zmq_to_scheduler \
  --port 30000
# encoder 1
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --encoder-only \
  --encoder-transfer-backend zmq_to_scheduler \
  --port 30001
# prefill 0
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --disaggregation-mode prefill \
  --language-only \
  --encoder-urls http://127.0.0.1:30000 http://127.0.0.1:30001 \
  --encoder-transfer-backend zmq_to_scheduler \
  --port 30002
# decode 0
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --disaggregation-mode decode \
  --port 30003
# router
sgl-router \
  --model-id Qwen/Qwen3-VL-8B-Instruct \
  --no-tokenizer \
  --worker-urls http://$PREFILL_HOST:30002 http://$DECODE_HOST:30003 \
  --port 8000

```

#### gRPC Encoder (EPD)

You can run the encoder as a gRPC server while keeping prefill/decode as HTTP.
When using gRPC encoders, set `SGLANG_ENCODER_MM_RECEIVER_MODE=grpc` for the
prefill process so it uses the gRPC receiver.

```bash Command
# gRPC encoder
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --encoder-only \
  --grpc-mode \
  --encoder-transfer-backend zmq_to_scheduler \
  --port 30000

# prefill (HTTP) - tell it to use gRPC receiver
SGLANG_ENCODER_MM_RECEIVER_MODE=grpc \
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --disaggregation-mode prefill \
  --language-only \
  --encoder-urls grpc://127.0.0.1:30000 \
  --encoder-transfer-backend zmq_to_scheduler \
  --port 30002

# decode (HTTP)
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-VL-8B-Instruct \
  --disaggregation-mode decode \
  --port 30003

# router
sgl-router \
  --model-id Qwen/Qwen3-VL-8B-Instruct \
  --no-tokenizer \
  --worker-urls http://$PREFILL_HOST:30002 http://$DECODE_HOST:30003 \
  --port 8000
```
