## Overview

A monokernel is a persistent kernel that runs most of a decoder layer, including its attention, its mixture-of-experts block and its tensor-parallel all-reduce, in one or two launches. In small-batch decoding, where launch gaps and collective latency dominate a step, this shortens the time per output token.

SGLang provides the framework (`sglang.experimental.monokernels`), and vendors provide the kernels as plugins. With `--enable-monokernel`, every decode and speculative-verify step that a plugin's spec serves runs on its kernels, and every other step (prefill, extend, larger batches) runs SGLang's standard path. The decision depends only on the step's CUDA graph key, so a captured graph replays it exactly.

## Plugins

| Plugin | GPUs | Models |
| --- | --- | --- |
| [sgl-amd-mono](https://github.com/sgl-project/sgl-amd-mono) | AMD Instinct MI350X, MI355X | DeepSeek-V4.1-Flash and its DSpark draft, TP2 and TP4 |

## Usage

```bash
pip install git+https://github.com/sgl-project/sgl-amd-mono.git
python -m sglang.launch_server \
  --model-path deepseek-ai/DeepSeek-V4.1-Flash \
  --tp 4 \
  --speculative-algorithm DSPARK \
  --speculative-dspark-block-size 5 \
  --fp8-gemm-backend aiter \
  --enable-monokernel
```

If no installed plugin covers the model on this GPU, or the setup uses a feature the plugin does not accept (for example pipeline parallelism, DP attention or LoRA), the server refuses to start and lists every reason.

## Checking which steps run monokernels

Routing depends only on a step's CUDA graph key and is fixed when the model loads, so the startup log states exactly which steps run the plugin's kernels. Each model logs one line, for example:

```text
monokernel deepseek_v41_hip on gfx950 runs target_verify steps of batch size [1, 2, 3, 4, 5, 6, 7, 8] x 6 tokens (8 of 20 decode graphs); every other step runs the standard path. ...
```

A server whose spec serves none of its steps refuses to start rather than running the standard path only.

## Writing a plugin

A monokernel plugin is an SGLang [general plugin](../hardware-platforms/plugin) that registers a spec for each model architecture it supports:

```toml pyproject.toml
[project.entry-points."sglang.srt.plugins"]
my_mono = "my_mono:register_specs"
```

```python my_mono/__init__.py
def register_specs():
    from sglang.experimental.monokernels import register

    register(architecture="DeepseekV4ForCausalLM", path="my_mono.deepseek_v41:SPEC")
```

A spec (`MonoSpec` in `sglang.experimental.monokernels.spec`) declares the GPUs, step widths and features it supports and its reasons to refuse a setup, and builds the model's kernels once the weights are loaded. The built model answers `serves(key)` for each CUDA graph key and provides `forward(plan, ...)`, which takes and returns what the model's own forward does. See [RFC #43949](https://github.com/sgl-project/sglang/issues/43949) for the design.
