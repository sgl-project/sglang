This page is the entry point for the Ascend NPU documentation set. It does not repeat the model tutorials or the tuning reference. Instead it collects the decisions that come before and after those pages: which model and card budget to start from, which precision to load, where published performance numbers come from, and where a specific error is documented.

Use it when you are choosing a configuration. Follow the linked page when you need the full command, the parameter reference, or a log excerpt.

## Search

The site search box covers every page in this section, including the keyword lists in each page header. Search for the exact string you see in a terminal first — error codes such as `507035`, `aclnnInplaceFillScalar`, or `op.preamble.length` resolve faster than descriptive phrases.

If a search returns several pages, prefer the one with a matching image tag and hardware series. Numbers and flags from different image versions are not interchangeable.

## What "validated" means

A configuration listed in this section is a published best practice, not a hardware ceiling:

- It was measured on the hardware series in its title with the image tag stated at the top of that page. The current baseline pages were validated with `quay.io/ascend/sglang:v0.5.18-cann9.0.0-a3`.
- The TPOT value is the latency target the configuration is tuned to. It is not an average over all possible traffic.
- The benchmark uses fixed-length random input and output (`--dataset-name random`, `--random-range-ratio 1`) so that two runs of the same configuration are comparable.

Reproduce a number on your own hardware before using it in a capacity plan. See [Performance baselines](/docs/hardware-platforms/ascend-npus/knowledge-base/performance-baselines) for the benchmark command and the caveats.

## Maintenance

This index is reviewed when any of the following happens:

- A new stable image tag replaces the tag used by the baseline pages.
- A model tutorial or best-practice page is merged, removed, or renamed.
- A published configuration no longer reproduces on the stated image tag.

To add an entry:

1. Reproduce the configuration and record the image tag, CANN version, driver version, card count, `--tp-size`, `--mem-fraction-static`, and the benchmark command.
2. Add the configuration to the model's best-practice page, including a summary row in its low-latency or high-throughput table.
3. Add the row to the deployment matrix above, and add a comparison entry to the performance baselines page if the new data supports one.
4. Keep the page keyword list current so the new entry is discoverable in search.

Open the change as a normal documentation pull request and link it to the model's tracking issue, following the [contribution guide](/docs/hardware-platforms/ascend-npus/development/contribution_guide).
