This page is a tuning method plus one worked example. The checklists and launch commands use the published
DeepSeek V3.2 PD configuration (32 NPUs, W8A8), so every value below traces back to a validated deployment.

Use it in one of three ways:

- **Tune for a goal**: start with [How to Tune](#how-to-tune), find the goal in [Tuning by Goal](#tuning-by-goal), then follow the
  [scenario checklist](#scenario-checklists) for your deployment shape.
- **Look up a flag**: open the [Feature Descriptions](#feature-descriptions) index at the top of the
  [Parameter Reference](#parameter-reference), or search for the flag name.
- **Check a combination**: read [Feature Compatibility](#feature-compatibility) before enabling several features together.

Full launch scripts for every model live under **Best Practices** in the sidebar, and each page names the image it was
validated on. This page explains the flags those scripts set and the conditions that change them. When you bump a pinned
image, take the script from the best-practice page rather than from here.

<Note>
  Parameters fall into two categories:

  - **Required** (marked `[Required]`, qualified when the requirement is scenario-specific, for example `[Required for
    multi-node]`): omitting it fails at startup, hangs, or silently produces wrong results.
  - **Tuning**: changes throughput, latency, or memory. The values here are starting points from the worked example, not
    defaults.
</Note>

## How to Tune

1. **Define the goal and measure a baseline.** Choose the target metric (TTFT, TPOT, throughput, or memory headroom) and
   benchmark the current configuration before changing anything. [Performance Testing](/docs/hardware-platforms/ascend-npus/evaluation/performance_testing)
   shows the command and how to read Mean TTFT/Mean TPOT. Record the seed, input/output lengths, and concurrency with
   every run. For a kernel-level view, use [Profiling](/docs/hardware-platforms/ascend-npus/optimization/profiling).
2. **Tune top-down.** Fix the topology first (parallelism, PD disaggregation), then the load-shape parameters that consume
   memory (`--chunked-prefill-size`, `--cuda-graph-max-bs-decode`, speculative decoding), and size
   `--mem-fraction-static` last: activation and graph buffers are inputs to the memory budget. Communication settings and
   the remaining kernel switches come after that. Choices at one level bound what the levels below can achieve, and
   graph-level tuning cannot compensate for a wrong TP/EP split.
3. **Change one parameter at a time, re-measure, and keep the better configuration.** Record every configuration you
   benchmark so the results stay comparable.
4. **Verify before keeping it.** After quantization or speculative decoding, run the
   [accuracy evaluation](/docs/hardware-platforms/ascend-npus/evaluation/accuracy_evaluation). After any change, re-run the
   same benchmark. Keep the previous configuration so you can roll back.

## Tuning by Goal

Where to start for common goals, ordered by expected impact. Each row names its cost and, where known, the failure mode
if the constraint is not met.

### Lower decode latency (TPOT)

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| [Speculative decoding](#speculative-decoding) | Verifies several draft tokens in one target forward | Draft compute; acceptance-rate dependent, so re-run the [accuracy evaluation](/docs/hardware-platforms/ascend-npus/evaluation/accuracy_evaluation) |
| [`SGLANG_NPU_USE_MLAPO=1`](#deepseek-specific-npu-optimizations) | Fuses MLA pre-processing into one kernel | DeepSeek-style MLA only; unsupported layouts run unfused, and a layout mismatch under a selected MLAProlog raises on the first forward |
| [`SGLANG_NPU_USE_MULTI_STREAM=1`](#deepseek-specific-npu-optimizations) | Runs shared and routed experts concurrently on separate streams | DeepSeek-style MoE only; adds cross-stream synchronization |
| [`--cuda-graph-max-bs-decode`](#decode-tuning) | Removes kernel-launch overhead | Capture time and memory; buckets that miss the graph batch-size alignment are dropped, and startup aborts if none survive — set it to at least the alignment and to a multiple of it |
| [`--attn-dp-size`](#parallelism) | More independent decode instances | Attention must not be the bottleneck; must divide TP |

If further reduction is needed: `SGLANG_SCHEDULER_SKIP_ALL_GATHER=1`, only with balanced DP load.

### Higher throughput

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| [`--attn-dp-size`](#parallelism) | More independent decode instances | Per-request latency can rise; must divide TP |
| [`--max-running-requests`](#prefill-tuning) | More concurrent requests per node | Per-request latency rises; the KV pool must fit them |
| [`--tokenizer-worker-num`](#throughput-tuning) | Parallelizes tokenization across multiple worker processes | Some features require `1` (native gRPC, elastic EP) |

Also consider: [`--ep-size`](#parallelism) (distribute experts across devices) and
[`--mem-fraction-static`](#memory-and-device-configuration) (more KV cache; monitor for out-of-memory errors).

### Lower time to first token (TTFT)

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| [`--chunked-prefill-size`](#prefill-tuning) on mixed workloads | Short requests are not delayed behind a single long prefill | A small prefill overhead per chunk |
| Prefix caching (leave [`--disable-radix-cache`](#prefill-tuning) unset) | Reuses KV of shared prompt prefixes | Radix-tree memory; no benefit without shared prefixes |
| [`--attn-cp-size`](#parallelism) for long inputs | Splits one long sequence across devices | More inter-device communication; requires the prefill CP flags |

### Resolve out-of-memory errors

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| Lower [`--mem-fraction-static`](#memory-and-device-configuration) | Leaves room for activations and graph buffers | Less KV cache, so fewer concurrent requests |
| [`--quantization modelslim`](#quantization) | W8/W4 checkpoints reduce weight memory by approximately 50%/75% | A small accuracy loss; re-run the [accuracy evaluation](/docs/hardware-platforms/ascend-npus/evaluation/accuracy_evaluation) |

Also consider: `PYTORCH_NPU_ALLOC_CONF=expandable_segments:True` (mitigates allocator fragmentation). If startup instead
fails with `Not enough memory … increase --mem-fraction-static`, the KV pool is too small: see
[Troubleshooting](#troubleshooting).

### Serve long contexts

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| [`--enable-prefill-cp`](#parallelism) + [`--attn-cp-size`](#parallelism) + [`--cp-strategy`](#parallelism) | Shards one sequence's KV and attention across devices | More communication; the strategy is model-specific; `--attn-cp-size` must divide TP |
| [`--max-prefill-tokens`](#prefill-tuning) | Total input-token budget per prefill batch; raise it so concurrent long requests co-batch in one forward | Large values need an explicit `--mem-fraction-static` |
| [`--chunked-prefill-size -1`](#prefill-tuning) on a dedicated prefill group | Entire sequence prefilled in one pass | No decode interleaving on that node |

### Scale beyond one node

| Parameter | Why it helps | Cost / constraint |
| --- | --- | --- |
| [PD disaggregation](#pd-disaggregation) | Prefill and decode tuned separately on their own nodes | More nodes and a router to operate |
| [Multi-Node](#multi-node) topology (`--nnodes`, `--node-rank`, `--dist-init-addr`) | Runs models that exceed a single node's memory | Copy the topology flags from your model's best-practice script; a wrong rank or init address hangs startup |

Also consider: `DEEPEP_HCCL_BUFFSIZE` per role (prefill `1200`, decode `400`); every multi-node role also requires
`HCCL_SOCKET_IFNAME` / `GLOO_SOCKET_IFNAME` set to an interface reachable from every node, or initialization hangs
(see [Communication Configuration](#communication-configuration)).

## Feature Compatibility

Check a combination here before you launch it. The table lists each combination, or missing companion, with a known
consequence, and every pair appears once, alphabetically by its first item so either side can be found.

- **Blocked**: fails at startup, hangs, or silently produces wrong results.
- **Conditional**: works only under the stated condition.

Absence from the table means no known conflict, not a guarantee. For per-flag support status, see
[Supported Features](/docs/hardware-platforms/ascend-npus/reference/support_features).

| Combination | Status | Consequence and fix |
| --- | --- | --- |
| [Attention DP](#parallelism) + `--dp-size` greater than 1 | Blocked | Model replicas cannot be combined with attention DP, and `--dp-size` greater than 1 is single-node only. |
| [EPLB](#moe-dispatch-and-expert-load-balancing) + `ascend_fuseep` backend | Blocked | EPLB requires `deepep`. There is no startup guard, so a wrong backend fails silently. |
| [EPLB](#moe-dispatch-and-expert-load-balancing) + topology where `TP ≠ EP ≠ world size` | Blocked | Migration asserts `tp_size == moe_ep_size == world_size`. |
| [HCCL](#communication-configuration) + `HCCL_OP_EXPANSION_MODE=AIV` on A2 with DeepEP | Blocked | Vendor docs report unknown-operator errors; leave it unset on that combination. |
| LoRA + [`SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1`](#speculative-decoding) | Blocked | The speculative plan stream is incompatible with LoRA under EAGLE/NEXTN/EAGLE3. |
| [NPU Graph](#decode-tuning) + `TASK_QUEUE_ENABLE=2` during capture | Blocked | torch_npu rejects level 2 during graph capture; use `0` or `1`. |
| [NPU Graph](#decode-tuning) + `--cuda-graph-max-bs-decode` below the batch-size alignment | Blocked | Buckets that miss the alignment are filtered out and the capture list comes back empty; the rule is in [Decode Tuning](#decode-tuning). |
| [NPU Graph](#decode-tuning) + deprecated `--disable-cuda-graph` where decode graphs are needed | Conditional | It still works, but it is global, so it disables decode capture too; use `--cuda-graph-backend-decode=disabled` instead. |
| [PD decode](#pd-disaggregation) + prefix caching | Conditional | Decode forces radix caching off; only the experimental `--disaggregation-decode-enable-radix-cache` re-enables it. |
| [PD disaggregation](#pd-disaggregation) + default transfer backend or unset `ASCEND_MF_STORE_URL` | Blocked | The default backend does not work on NPU, and decode nodes find the KV-transfer service through the store. Set `--disaggregation-transfer-backend ascend` and the same `ASCEND_MF_STORE_URL` on every node. |
| [PD prefill](#pd-disaggregation) + `--load-balance-method round_robin` | Conditional | Keep `auto`: prefill resolves to `follow_bootstrap_room` and decode to `round_robin`, and an explicit round-robin loses bootstrap-room affinity. |
| [Prefill CP](#parallelism) + missing `--cp-strategy` | Blocked | Startup fails with `--cp-strategy must be set when --enable-prefill-cp is enabled`. Add `interleave` for DeepSeek V3.2 or `zigzag` for MiMo V2. |
| [`SGLANG_SCHEDULER_SKIP_ALL_GATHER=1`](#parallelism) + uneven DP load | Conditional | Safe only when every DP rank sees the same forward mode and token counts. Uneven load desyncs MoE dispatch and graph buckets silently, and no startup guard catches it. |
| [Speculative decoding](#speculative-decoding) + quantized target model | Conditional | The draft inherits the target quantization; pass `--speculative-draft-model-quantization unquant`. |

The worked example runs NPU Graph, TP, attention DP, EP, PD disaggregation, quantization, speculative decoding, and DP LM
Head together on the decode side; the [scenario checklists](#scenario-checklists) give the exact combination.

## Scenario Checklists

Ordered starting points for each deployment shape. Values and commands come from the V3.2 PD worked example unless
another model is noted. The single-node checklist is decisions only, because no single-node V3.2 configuration is
published: take the values from your model's best-practice page.

### Single-Node Mixed Serving

Both prefill and decode run on the same node, so each setting below must hold for both phases. Apply them in this order:

<Steps>
  <Step title="Set the topology">
    `--tp-size` = the number of NPUs used. For MoE models, add `--moe-a2a-backend deepep`; the EP size then follows TP.

    **Why:** topology constrains everything else. See [Parallelism](#parallelism).
  </Step>

  <Step title="Keep chunked prefill enabled">
    Leave chunked prefill on. The default comes from the device-memory heuristic: `4096` on devices up to 32 GB,
    `8192` on devices above 32 GB and below 160 GB, and `16384` at 160 GB and above.

    **Why:** chunking interleaves prefill with decode in mixed workloads.
  </Step>

  <Step title="Keep NPU Graph on and size the decode buckets">
    Leave NPU Graph enabled, and set `--cuda-graph-max-bs-decode` near your typical per-rank batch size, at a multiple of
    the graph batch-size alignment (see [Decode Tuning](#decode-tuning)).

    **Why:** graphs remove kernel-launch overhead; batches beyond the captured maximum run without a graph.
  </Step>

  <Step title="Add speculative decoding (optional)">
    Use `NEXTN` for models with a multi-token-prediction (MTP) head, and `EAGLE3` otherwise.

    **Why:** it reduces per-token latency.
  </Step>

  <Step title="Size the memory fraction after everything else">
    With the topology, graph, and speculative settings already fixed, size `--mem-fraction-static`. Start from a
    same-class best practice, lower it if out-of-memory errors occur, and raise it when KV cache capacity limits
    concurrency.

    **Why:** activation and graph buffers are inputs to the memory budget. See
    [Memory and Device Configuration](#memory-and-device-configuration).
  </Step>

  <Step title="Leave the task queue at level 1">
    Keep `TASK_QUEUE_ENABLE` at `1` on a mixed node.

    **Why:** mixed nodes capture decode graphs, and level `2` is incompatible with graph capture.
  </Step>
</Steps>

### PD Disaggregation (by Role)

Prefill and decode run on separate node groups, and one router exposes both as a single service. Each tab gives the
decisions for that role, followed by the complete launch command from the published configuration. Both roles load the
same ModelSlim checkpoint (`--quantization modelslim`), which cuts the weight footprint versus BF16; only the budget left
for KV cache differs between the roles, which is why their memory fractions differ. See [Quantization](#quantization).

<Tabs>
  <Tab title="Prefill">

The prefill group runs prefill only, so it can take large un-chunked batches and leave graph capture off. Apply the
decisions in order, then use the command below.

<Steps>
  <Step title="Join the group as prefill">
    Set the role, the transfer backend, the bootstrap port, and the store URL. The MemFabric rendezvous store is the
    service that lets decode nodes find the prefill KV-transfer endpoint; it runs on the `node_rank 0` prefill node, and
    every prefill and decode node sets the same URL.

    **Why:** the default transfer backend does not work on NPU, and the router and decode nodes reach the prefill
    bootstrap service through that port. See the [Glossary](/docs/hardware-platforms/ascend-npus/reference/glossary) if
    MemFabric is new to you.
  </Step>

  <Step title="Shape batches for long sequences">
    Disable chunking, set the token budget to the target sequence length, hold concurrency at `1`, and pin the memory
    fraction explicitly. The published command also disables radix caching, which suits random-input benchmarks and
    dedicated prefill nodes; turn caching back on when traffic shares long prompt prefixes.

    **Why:** the group does not interleave with decode, so one request can use the whole node. The token budget and the
    memory fraction are coupled: a large `--max-prefill-tokens` needs an explicit `--mem-fraction-static`, because the
    automatic heuristic would otherwise reserve about 1.5 MB per token for activations.
  </Step>

  <Step title="Keep graph capture off and raise the task queue">
    NPU prefill graphs are off by default, so the command disables nothing globally. Set `TASK_QUEUE_ENABLE=2` on this
    role.

    **Why:** graphs add little for large, variable prefill batches, and level `2` is safe here precisely because this role
    captures no graphs. On a mixed node it would break decode capture.
  </Step>

  <Step title="Add context parallelism for long contexts">
    The published configuration enables prefill CP with the CP size equal to TP and passes the model's strategy.
    DeepSeek V3.2 requires `interleave`; MiMo V2 requires `zigzag`. Skip CP on prefill nodes that only see short inputs.
    With `cp = tp` the attention layers are no longer TP-sharded, so the command also passes `--moe-dense-tp-size 1` to
    keep the dense FFN unsharded.

    **Why:** it distributes the KV cache across devices. `--cp-strategy` is mandatory whenever `--enable-prefill-cp` is
    set, and `--attn-cp-size` must divide TP.
  </Step>

  <Step title="Keep speculative decoding shallow">
    The command keeps the model's MTP head active with fewer steps than decode: one draft step and two draft tokens.

    **Why:** draft steps add latency, and prefill has little acceptance length to gain from them. Decode uses three steps
    and four tokens for the same reason. See [Speculative Decoding](#speculative-decoding).
  </Step>

  <Step title="Use DeepEP normal mode and quantize dispatch">
    Select `deepep` with `normal` mode, and prefer the dispatcher dtype flag over the deprecated environment variable.

    **Why:** normal mode is the bulk dispatch path for large token counts, and INT8 dispatch reduces communication volume
    on multi-node prefill.
  </Step>
</Steps>

**Launch command** (published configuration, 32 NPUs over 2 nodes):

```bash
# ============================================================
# DeepSeek V3.2 PD prefill - published configuration.
# Run on every prefill node and replace the <...> placeholders.
# The multi-node loop wrapper is in the V3.2 best-practice page.
# Cluster-wide exports (PYTORCH_NPU_ALLOC_CONF, SGLANG_SET_CPU_AFFINITY,
# STREAMS_PER_DEVICE) are described in System-Level Optimizations and
# Memory and Device Configuration.
# Flags this page does not cover (parsers, watchdog timeout, trust-remote-code,
# device, attention backend) are carried over from the validated script.
# ============================================================
export ASCEND_MF_STORE_URL="tcp://<prefill-primary-ip>:24670"   # same value on every node
export HCCL_SOCKET_IFNAME=<network-interface>
export GLOO_SOCKET_IFNAME=<network-interface>
export DEEPEP_HCCL_BUFFSIZE=1200
export TASK_QUEUE_ENABLE=2

python3 -m sglang.launch_server \
    --model-path <model-path> \
    --device npu \
    --attention-backend ascend \
    --disaggregation-mode prefill \
    --disaggregation-transfer-backend ascend \
    --disaggregation-bootstrap-port 8998 \
    --host <prefill-node-ip> --port 8000 \
    --dist-init-addr <prefill-primary-ip>:5000 \
    --nnodes 2 --node-rank <0-or-1> \
    --tp 32 \
    --quantization modelslim \
    --mem-fraction-static 0.73 \
    --chunked-prefill-size -1 \
    --max-prefill-tokens 68000 \
    --max-running-requests 1 \
    --disable-radix-cache \
    --moe-a2a-backend deepep \
    --deepep-mode normal \
    --deepep-dispatcher-output-dtype int8 \
    --moe-dense-tp-size 1 \
    --enable-prefill-cp \
    --attn-cp-size 32 \
    --cp-strategy interleave \
    --speculative-algorithm NEXTN \
    --speculative-num-steps 1 \
    --speculative-eagle-topk 1 \
    --speculative-num-draft-tokens 2 \
    --reasoning-parser deepseek-v3 \
    --tool-call-parser deepseekv32 \
    --trust-remote-code \
    --watchdog-timeout 9000
```

The script published for the pinned image `quay.io/ascend/sglang:v0.5.18-cann9.0.0-a3` differs on three lines, all
explained above: it passes `--cp-strategy zigzag`, keeps the deprecated `--disable-cuda-graph`, and sets
`DEEP_NORMAL_MODE_USE_INT8_QUANT=1` instead of the dispatcher dtype flag. Keep those spellings only while you stay on that
image.

  </Tab>

  <Tab title="Decode">

Decode is latency-bound, so these decisions keep per-rank batches small and capture graphs. Apply them in order, then use
the command below.

<Steps>
  <Step title="Join the group as decode">
    Set the role, the transfer backend, and the same store URL the prefill group uses, and serve on the decode port.

    **Why:** decode nodes discover the KV transfer service through the store. With a wrong address a decode node still
    starts, but no request ever reaches it.
  </Step>

  <Step title="Enable attention DP and the DP LM head">
    Set the attention DP size, enable the DP LM head, set the EP size, and pass `--moe-dense-tp-size 1` so the dense FFN
    is replicated per DP group instead of all-reduced. With `deepep`, EP is forced to TP, so the published configuration
    passes the full TP size.

    **Why:** attention DP removes KV duplication across the TP group, and the DP LM head shards the vocabulary once
    attention DP is on. Each DP group already holds the full dense weights, so sharding the dense FFN across TP would add
    a gather for nothing.
  </Step>

  <Step title="Use the low-latency dispatch path">
    Select `low_latency` mode, cap concurrency, and size the per-rank dispatch buffer to the tokens one rank actually
    dispatches per iteration.

    **Why:** low-latency mode is the small-batch path, and oversizing the buffer pads every iteration. See
    [Sizing the DeepEP dispatch buffer](#sizing-the-deepep-dispatch-buffer) for the formula; the published `8` leaves
    headroom over the benchmark load of one request per DP rank × 4 verify tokens.
  </Step>

  <Step title="Capture small decode graphs">
    Turn the task queue off and set the maximum decode batch size near your typical per-rank batch size.

    **Why:** decode captures NPU graphs, and level `2` is incompatible with capture; batches beyond the captured maximum
    run without a graph.
  </Step>

  <Step title="Reduce per-step latency">
    Enable speculative decoding, move its batch preparation onto a dedicated stream, and skip the scheduler all-gather
    when DP load is balanced.

    **Why:** speculative decoding reduces per-token latency, and skipping the all-gather removes a synchronization point.
    Skipping is safe only when every DP rank sees the same forward mode and the same token counts.
  </Step>
</Steps>

**Launch command** (published configuration, 32 NPUs over 2 nodes):

```bash
# ============================================================
# DeepSeek V3.2 PD decode - published configuration.
# Run on every decode node and replace the <...> placeholders.
# Cluster-wide exports (PYTORCH_NPU_ALLOC_CONF, SGLANG_SET_CPU_AFFINITY,
# STREAMS_PER_DEVICE) are described in System-Level Optimizations and
# Memory and Device Configuration.
# Flags this page does not cover (parsers, watchdog timeout, trust-remote-code,
# device, attention backend) are carried over from the validated script.
# ============================================================
export ASCEND_MF_STORE_URL="tcp://<prefill-primary-ip>:24670"   # same value on every node
export HCCL_SOCKET_IFNAME=<network-interface>
export GLOO_SOCKET_IFNAME=<network-interface>
export DEEPEP_HCCL_BUFFSIZE=400
export SGLANG_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK=8
export SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1
export SGLANG_SCHEDULER_SKIP_ALL_GATHER=1   # only with balanced DP load
export TASK_QUEUE_ENABLE=0

python3 -m sglang.launch_server \
    --model-path <model-path> \
    --device npu \
    --attention-backend ascend \
    --disaggregation-mode decode \
    --disaggregation-transfer-backend ascend \
    --host <decode-node-ip> --port 8001 \
    --dist-init-addr <decode-primary-ip>:5000 \
    --nnodes 2 --node-rank <0-or-1> \
    --tp 32 \
    --attn-dp-size 8 \
    --ep 32 \
    --moe-dense-tp-size 1 \
    --enable-dp-lm-head \
    --quantization modelslim \
    --mem-fraction-static 0.79 \
    --max-running-requests 32 \
    --cuda-graph-max-bs-decode 4 \
    --moe-a2a-backend deepep \
    --deepep-mode low_latency \
    --disable-radix-cache \
    --chunked-prefill-size -1 \
    --max-prefill-tokens 68000 \
    --speculative-algorithm NEXTN \
    --speculative-num-steps 3 \
    --speculative-eagle-topk 1 \
    --speculative-num-draft-tokens 4 \
    --reasoning-parser deepseek-v3 \
    --tool-call-parser deepseekv32 \
    --trust-remote-code \
    --watchdog-timeout 9000
```

The published script writes `--enable-dp-attention --dp-size 8`; that spelling is deprecated and equivalent to
`--attn-dp-size 8`. It also passes `--ep 32` explicitly, which matches the EP size `deepep` forces anyway.

The script further carries three prefill-side flags on decode (`--disable-radix-cache`, `--chunked-prefill-size -1`, and
`--max-prefill-tokens 68000`). They do no work in this role, and PD decode forces radix caching off regardless, so keep
them only to stay aligned with the validated script.

  </Tab>

  <Tab title="Router">

One router serves both groups and exposes a single OpenAI-compatible endpoint. Start it after both groups are up:

<Steps>
  <Step title="Reuse the prefill bootstrap port">
    Point the router at the same bootstrap port the prefill group sets.

    **Why:** the router passes that port to decode nodes when it opens the prefill connection.
  </Step>

  <Step title="Launch the router">

    ```bash
    # ============================================================
    # Before running, replace the following placeholders:
    #   <your prefill ip>: prefill node IP address
    #   <your decode ip>: decode node IP address
    # ============================================================
    python -m sglang_router.launch_router --pd-disaggregation \
      --policy cache_aware \
      --prefill http://<your prefill ip>:8000 8998 \
      --decode http://<your decode ip>:8001 \
      --host 127.0.0.1 --port 6688 --mini-lb
    ```

    **Why:** it exposes one endpoint; without the router the two groups are not reachable as a single service.
  </Step>
</Steps>

### Multi-Node

These settings matter once prefill or decode spans more than one node. They extend the single-node or PD decisions above
rather than replace them. Apply them in this order:

<Steps>
  <Step title="Pin the HCCL and Gloo interfaces">
    **[Required for multi-node]** Set `HCCL_SOCKET_IFNAME` / `GLOO_SOCKET_IFNAME` to an interface reachable from every
    node.

    **Why:** when the variable is unset the framework auto-selects an interface, and an unreachable choice makes
    initialization hang or fail. See [Communication Configuration](#communication-configuration).
  </Step>

  <Step title="Size the DeepEP HCCL buffers per role">
    Set `DEEPEP_HCCL_BUFFSIZE` to `1200` on prefill and `400` on decode.

    **Why:** larger buffers carry bulk inter-node transfers but cost HBM, and decode needs less.
  </Step>

  <Step title="Quantize dispatch on prefill">
    Pass the dispatcher dtype flag on multi-node prefill, or the deprecated environment variable on older builds.

    **Why:** it lowers dispatch traffic across nodes. See
    [MoE Dispatch and Expert Load Balancing](#moe-dispatch-and-expert-load-balancing).
  </Step>

  <Step title="Copy the topology flags from the best-practice script">
    **[Required for multi-node]** Set `--nnodes`, `--node-rank`, and `--dist-init-addr` from the best-practice script for
    your model.

    **Why:** a wrong rank or init address leaves the group hanging at startup. The published scripts carry the complete
    validated set for each model.
  </Step>
</Steps>

Model-specific extras are not multi-node requirements and live with the model switches. One example is
`SGLANG_USE_AG_AFTER_QLORA=1` with `--enable-attn-tp-input-scattered` on DeepSeek R1 prefill; see
[DeepSeek-Specific NPU Optimizations](#deepseek-specific-npu-optimizations).

## Troubleshooting

| Symptom | Likely Cause | Fix |
| ------- | ------------ | --- |
| Startup fails with `Not enough memory. Please try to increase --mem-fraction-static` | The KV pool computed to zero (or negative) capacity once weights were loaded | Increase `--mem-fraction-static` in small steps; the message means the pool is too small, not that the model is too large |
| Out of memory during serving or graph capture | `--mem-fraction-static` leaves no headroom for activations or graph buffers, or the weights are BF16 | Lower `--mem-fraction-static`; if the model is BF16, load a ModelSlim W8A8/W4A4 checkpoint (`--quantization modelslim` loads pre-quantized checkpoints only; quantize your own with msModelSlim, see [Quantization on Ascend](/docs/hardware-platforms/ascend-npus/optimization/quantization)) |
| NPU Graph capture aborts with `Do not support TASK_QUEUE_ENABLE = 2 during NPU graph capture` | Level-2 task queue is incompatible with graph capture | Set `TASK_QUEUE_ENABLE=0` (or `1`) on the role that captures graphs |
| NPU Graph capture aborts with an `AssertionError` whose message is `capture_bs=[]` | Every decode bucket missed the batch-size alignment, so the capture list is empty | Raise `--cuda-graph-max-bs-decode` to at least the alignment width and to a multiple of it, or narrow the alignment by removing attention DP or the MoE all-to-all backend; see [Decode Tuning](#decode-tuning) |
| DeepEP dispatch fails at runtime | Per-rank dispatch tokens exceed the buffer | Size `SGLANG_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK` to the actual per-iteration maximum; see [Sizing the DeepEP dispatch buffer](#sizing-the-deepep-dispatch-buffer) |
| Multi-node HCCL/Gloo initialization hangs or fails | Auto-selected interface not reachable across nodes | Set `HCCL_SOCKET_IFNAME` / `GLOO_SOCKET_IFNAME` to an interface reachable from every node |
| PD decode node fails to start | Transfer backend left at the default, or a wrong store address | Pass `--disaggregation-transfer-backend ascend` and set `ASCEND_MF_STORE_URL=tcp://<prefill-primary-ip>:<port>` |
| Intermittent pinned host memory allocation failures | Pinned host pool fragmentation | Append `pin_memory_expandable_segments:True` to `PYTORCH_NPU_ALLOC_CONF`; requires CANN 8.5.0 / driver 25.5.0 or newer (the driver check is waived on Ascend 950 and newer), otherwise the setting is reset to `False` with a one-time warning |
| Expert hotspots or uneven load across NPUs | Static expert placement | `--enable-eplb` (requires the `deepep` backend, `TP = EP = world size`, and `--ep-num-redundant-experts`) |
| Startup fails with `--cp-strategy must be set when --enable-prefill-cp is enabled` | Prefill CP enabled without a strategy | Add `--cp-strategy interleave` for DeepSeek V3.2, or `zigzag` for MiMo V2 |
| PD decode starts but requests never reach the prefill bootstrap | Missing or wrong `--disaggregation-bootstrap-port`, or the router was not launched | Set the port on the prefill group and pass the same port in the router's `--prefill` address |

#### Sizing the DeepEP dispatch buffer

Size `SGLANG_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK` to the maximum number of tokens one rank dispatches per decode
iteration: running requests per rank × `--speculative-num-draft-tokens` with speculative decoding, or just the running
requests per rank without it.

The published value `8` leaves headroom over its benchmark load: 8 concurrent requests over DP 8 is one request per
rank, which is `1 × 4 = 4` dispatched tokens per iteration, half the buffer. Serving the full `--max-running-requests 32`
cap would need `(32 / 8) × 4 = 16`, so raise the value when you serve more concurrency than the benchmark did.

Two consequences follow from how the value is used. Low-latency dispatch pads to the configured value every iteration, so
an oversized buffer avoids the runtime failure but adds padding cost on every step. And `ascend_fuseep` gives the
variable different semantics (mode 2 treats it as received-token capacity), so the DeepEP formula does not carry over.

chunking on, the reserve follows `--chunked-prefill-size` instead. Separately, NPU prefill graphs are off by default, so

graphs on a mixed node.

#### Graph batch-size alignment

Decode buckets are filtered against a batch-size alignment. The alignment is `attn_tp_size` whenever a gathered buffer is
in use: attention DP, any MoE all-to-all backend, or an explicit `--moe-dense-tp-size`; otherwise it is `1`. Two-batch
overlap multiplies the alignment by `2`, and context parallelism can raise it further. A bucket survives when its batch
size times the tokens one request contributes per decode step is a multiple of the alignment — with speculative decoding
those per-request draft tokens already satisfy part of the alignment, so buckets below it can survive. Buckets that miss
the alignment are dropped, and startup aborts if none survive.

In practice, set `--cuda-graph-max-bs-decode` to at least the alignment and to a multiple of it whenever attention DP, an
all-to-all backend, or `--moe-dense-tp-size` is in play. A dense model with plain TP has no such constraint.

### Speculative Decoding

Speculative decoding drafts several tokens per step and verifies them in one target forward pass, reducing per-token
latency. For non-greedy requests, Ascend target verification applies request-level `temperature`, `top_k`, and `top_p`.
Classic rejection sampling is also available via `--speculative-use-rejection-sampling`: it supports linear candidates
only, requires `--speculative-eagle-topk 1`, and is incompatible with non-default accept thresholds and deterministic
inference.

### DeepSeek-Specific NPU Optimizations

These switches optimize DeepSeek-style MLA (multi-head latent attention) attention and MoE layers. They are used in the
DeepSeek best practices and may apply to similar architectures.

<table>
  <thead>
    <tr>
      <th>Variable</th>
      <th>Purpose</th>
      <th>Reference Value</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`SGLANG_NPU_USE_MLAPO=1`</td>
