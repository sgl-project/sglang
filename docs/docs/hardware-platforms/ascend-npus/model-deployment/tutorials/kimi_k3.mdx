## Introduction

Kimi-K3 is an open-source Mixture-of-Experts (MoE) model developed by Moonshot AI, with 2.8 trillion total parameters and
16 active experts out of 896. It uses a hybrid linear attention architecture (Kimi Delta Attention, KDA), which requires
a Mamba-style state cache (`--max-mamba-cache-size`) during deployment. The model supports a native 1 million token
context window.

This document demonstrates the deployment of Kimi-K3 on Ascend NPUs using SGLang, including multi-node PD mixed mode with
**DSPARK** speculative decoding.

This document is validated and written based on the **SGLang daily build** (Docker image tag `cann9.0.0-a3-main`).
Performance and feature coverage will continue to be optimized in subsequent releases.

## Supported features

| Feature               | Example usage                                                                                                                                                                                                              |
|-----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Tensor Parallelism    | `--tp-size 64`                                                                                                                                                                                                             |
| Data Parallelism      | `--enable-dp-attention \`<br/>`--dp-size 4`                                                                                                                                                                                |
| Expert Parallelism    | `--moe-a2a-backend deepep \`<br/>`--deepep-mode auto`                                                                                                                                                                      |
| Quantization          | `--quantization modelslim`                                                                                                                                                                                                 |
| Chunked Prefill       | auto based on device memory, or set explicit value;<br/>e.g., `--chunked-prefill-size 16384`                                                                                                                               |

| DP LM Head            | `--enable-dp-lm-head`                                                                                                                                                                                                      |

### Model weights

Before downloading model weights, check the model size to reserve enough disk space.
For multi-node deployment, download the weights to a shared directory accessible to all nodes.

- [Kimi-K3-W4A8](https://www.modelscope.cn/models/sgl-npu/Kimi-K3-W4A8) (W4A8 INT8 quantized version, 1.49TB)
- [Kimi-K3-DSpark](https://www.modelscope.cn/models/RadixArk/Kimi-K3-DSpark) (DSPARK draft model for speculative decoding, 4.5GB)

<Info>
We recommend deploying the W4A8 variant for reduced resource usage and higher throughput.
It (1.49TB) can be deployed on 64 × 64GB of device memory (`--tp-size 64`), which corresponds to 4 full A3 nodes (32 cards).
</Info>

For the hardware specifications (memory per die, dies per card, and the difference between A2 and A3),
see [Ascend NPU Reference — Hardware](/docs/hardware-platforms/ascend-npus/reference/glossary#hardware).

## Online service deployment

### Multi-node online deployment (PD mixed with DSPARK)

Multi-node deployment distributes Kimi-K3 across multiple Atlas 800I A3 nodes using tensor parallelism while keeping
prefill and decode on the same nodes (PD mixed mode). This configuration uses **DSPARK** speculative decoding, which is
the recommended decoding acceleration method for Kimi-K3.

```bash Command
# ============================================================
# Before running, update the following variables:
#   MODEL_PATH: path to the model weights directory
#   DRAFT_MODEL_PATH: path to the DSPARK draft model weights directory
#   NODE_IPS: IP addresses of each node in the cluster (4 nodes)
#   HCCL_SOCKET_IFNAME: network interface name for HCCL
#   GLOO_SOCKET_IFNAME: network interface name for Gloo
# ============================================================

MODEL_PATH=/path/to/model-weights
DRAFT_MODEL_PATH=/path/to/draft-model-weights

NODE_IPS=('<your node1 ip>' '<your node2 ip>' '<your node3 ip>' '<your node4 ip>')

echo performance | tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor
sysctl -w vm.swappiness=10
sysctl -w kernel.numa_balancing=0
sysctl -w kernel.sched_migration_cost_ns=50000

unset https_proxy
unset http_proxy
unset HTTPS_PROXY
unset HTTP_PROXY

source /usr/local/Ascend/ascend-toolkit/set_env.sh
source /usr/local/Ascend/nnal/atb/set_env.sh

export GLOO_SOCKET_IFNAME=<network-interface>
export HCCL_SOCKET_IFNAME=<network-interface>
export PYTORCH_NPU_ALLOC_CONF=expandable_segments:True
export SGLANG_SET_CPU_AFFINITY=1
export SGLANG_ONE_VISIBLE_DEVICE_PER_PROCESS=1
export SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1
export STREAMS_PER_DEVICE=32
export DEEP_NORMAL_MODE_USE_INT8_QUANT=1
export SGLANG_DEEPEP_NUM_MAX_DISPATCH_TOKENS_PER_RANK=128
export HCCL_BUFFSIZE=200
export HCCL_OP_EXPANSION_MODE=AIV
export DEEPEP_NORMAL_LONG_SEQ_ROUND=64
export DEEPEP_NORMAL_LONG_SEQ_PER_ROUND_TOKENS=512
export DEEPEP_HCCL_BUFFSIZE=1800

# K3-specific optimizations
export SGLANG_K3_SHARED_EXPERTS_ATTN_TP=1
export SGLANG_K3_DENSE_MLP_ATTN_TP=1
export SGLANG_NPU_USE_TRITON_PREFIX_KV_CACHE_STORE=1

# DSPARK speculative decoding
export SGLANG_ENABLE_SPEC_V2=1
export SGLANG_RAGGED_VERIFY_MODE=static
export SGLANG_DSPARK_FOLDED_PROPOSAL=0
export SGLANG_DSPARK_FOLDED_SAMPLING=0
export SGLANG_DSPARK_STACKED_CTX_KV=0
export SGLANG_DSPARK_EMBED_IN_GRAPH=0

LOCAL_HOST1=`hostname -I|awk -F " " '{print$1}'`
LOCAL_HOST2=`hostname -I|awk -F " " '{print$2}'`
echo "${LOCAL_HOST1}"
echo "${LOCAL_HOST2}"

for i in "${!NODE_IPS[@]}";
do
    if [[ "$LOCAL_HOST1" == "${NODE_IPS[$i]}" || "$LOCAL_HOST2" == "${NODE_IPS[$i]}" ]];
    then
        echo "${NODE_IPS[$i]}"
        python3 -m sglang.launch_server \
            --model-path $MODEL_PATH \
            --tokenizer-path $MODEL_PATH \
            --dist-init-addr ${NODE_IPS[0]}:5000 \
            --nnodes 4 \
            --node-rank $i \
            --host 0.0.0.0 \
            --port 30000 \
            --trust-remote-code \
            --attention-backend ascend \
            --device npu \
            --quantization modelslim \
            --dtype bfloat16 \
            --tp-size 64 \
            --enable-dp-attention \
            --dp-size 4 \
            --enable-dp-lm-head \
            --mem-fraction-static 0.78 \
            --chunked-prefill-size 16384 \
            --cuda-graph-bs 2 4 8 16 \
            --max-running-requests 64 \
            --max-mamba-cache-size 64 \
            --moe-a2a-backend deepep \
            --deepep-mode auto \
            --speculative-algorithm DSPARK \
            --speculative-draft-model-path $DRAFT_MODEL_PATH \
            --speculative-dspark-block-size 7 \
            --speculative-draft-attention-backend ascend \
            --speculative-eagle-topk 1 \
            --speculative-draft-model-quantization unquant \
            --reasoning-parser kimi_k3 \
            --watchdog-timeout 9000 \
            --model-loader-extra-config '{"enable_multithread_load": true}'
        break
    fi
done
```

## Functional verification

After the service is started, you can invoke the model by sending a prompt:

```shell
# ============================================================
# Before running, update the following variables:
#   HOST: the server host address (e.g., localhost)
#   PORT: the server port number (e.g., 30000)
# ============================================================

curl http://${HOST}:${PORT}/generate \
    -H "Content-Type: application/json" \
    -d '{
        "text": "What is the capital of France?",
        "sampling_params": {
            "max_new_tokens": 64,
            "temperature": 0
        }
    }'
```

Expected result: an HTTP 200 response with the generated text containing "Paris".

Once the server prints `The server is fired up and ready to roll!` in the logs, it is ready to accept requests. For more
testing examples (Health Check, Generate, Chat Completions, and port usage guidance),
see [Testing the Service](/docs/hardware-platforms/ascend-npus/getting-started/installation#testing-the-service).
