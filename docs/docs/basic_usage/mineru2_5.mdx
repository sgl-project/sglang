MinerU2.5-2509-1.2B is a 1.2B-parameter, Qwen2-VL-based document-parsing vision-language model. It extracts layout, tables, and formulas from document images and renders them to Markdown. Its architecture is `Qwen2VLForConditionalGeneration` (config `model_type: qwen2_vl`), which SGLang serves through its Qwen2-VL implementation. The reference evaluation below used SGLang 0.5.12.post1 on a single NVIDIA H200 GPU.

## Launch server

On Linux with NVIDIA CUDA, use a current SGLang installation and launch one GPU:

```shell
sglang serve opendatalab/MinerU2.5-2509-1.2B \
  --mm-feature-transport cuda_ipc \
  --host 0.0.0.0 --port 30000
```

`--mm-feature-transport cuda_ipc` transfers image features through a bounded GPU pool on a single node. When the pool is full, features fall back to CPU transport. The default port `30000` matches the client examples below.

For SGLang 0.5.12.post1, the reference evaluation used the legacy transport setting:

```shell
SGLANG_USE_CUDA_IPC_TRANSPORT=1 \
python3 -m sglang.launch_server \
  --model-path opendatalab/MinerU2.5-2509-1.2B \
  --host 0.0.0.0 --port 30000
```

The checkpoint provides its chat template. To reduce the server's memory budget when sharing a GPU, set `--mem-fraction-static` to fit your workload.

## Parse documents with mineru-vl-utils

Point the [`mineru-vl-utils`](https://github.com/opendatalab/mineru-vl-utils) library at the running SGLang server via its `http-client` backend:

```shell
pip install -U mineru-vl-utils
```

```python
from PIL import Image
from mineru_vl_utils import MinerUClient

client = MinerUClient(backend="http-client", server_url="http://127.0.0.1:30000")
image = Image.open("page.png").convert("RGB")
blocks = client.two_step_extract(image)
print(blocks)
```

## Use with the MinerU pipeline CLI

The [MinerU 2.5.4](https://pypi.org/project/mineru/2.5.4/) pipeline can call the SGLang server through its remote VLM client:

```shell
pip install "mineru==2.5.4"
mineru -p input.pdf -o output -b vlm-http-client -u http://127.0.0.1:30000
```

`vlm-http-client` is the lightweight remote client backend: it talks to the SGLang server over HTTP and does not require a local `torch` install.

## Note on repetition control

The vLLM serving path enforces anti-repetition with `MinerULogitsProcessor` (via `vllm serve --logits-processors mineru_vl_utils:MinerULogitsProcessor`), which implements the `no_repeat_ngram_size` sampling parameter. SGLang has no built-in `no_repeat_ngram_size` sampling param, so the value the `mineru-vl-utils` `http-client` backend sends inside `vllm_xargs` is ignored by the server.

Dense repeated tables, noise, or blur can trigger repetition. SGLang supports `repetition_penalty`, `frequency_penalty`, `presence_penalty`, `min_p`, and `top_k`. Current `mineru-vl-utils` defaults use `presence_penalty=1.0` for content extraction, with `frequency_penalty=0.05` for text and equations and `0.005` for tables.

Hard n-gram blocking requires a client integration with a [custom logit processor](/docs/basic_usage/sampling_params#custom-logit-processor). Implement a `CustomLogitProcessor` that masks repeated n-grams using each request's generated token history, start SGLang with `--enable-custom-logit-processor`, and send the processor's `to_str()` value as `custom_logit_processor` in the OpenAI request's `extra_body`. The stock `mineru-vl-utils` client sends `no_repeat_ngram_size` through `vllm_xargs`; adapting its HTTP request construction is required to attach an SGLang processor.

## Reference accuracy

On a single NVIDIA H200 GPU with SGLang 0.5.12.post1, MinerU2.5-2509-1.2B scores on OmniDocBench v1.6 (full set, 1651 pages, official `pdf_validation.py` end2end `quick_match`): text-block edit distance 0.0453, Table TEDS 87.94 (structure-only 91.78), reading-order edit distance 0.1304, and display-formula edit distance ~0.49 (the CDM metric is skipped as it requires LaTeX/Ghostscript/ImageMagick). Throughput: all 1651 pages extracted in ~23 minutes at client concurrency 24 (`aio_concurrent_two_step_extract`), about 0.84 s/page for the two-step layout + content pass.
