## 二、操作记录

### 使用Qwen3.8-27B权重

#### 1. 启动命令

```bash
# 主机性能设置
echo performance | tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor
sysctl -w vm.swappiness=0
sysctl -w kernel.numa_balancing=0
sysctl -w kernel.sched_migration_cost_ns=50000
unset https_proxy http_proxy HTTPS_PROXY HTTP_PROXY ASCEND_LAUNCH_BLOCKING
source /usr/local/Ascend/ascend-toolkit/set_env.sh
source /usr/local/Ascend/nnal/atb/set_env.sh

export ASCEND_USE_FIA=1
export GDN_ATTN_BACKEND_TRITON=1
export GLOO_SOCKET_IFNAME=lo
export HCCL_OP_EXPANSION_MODE=AIV
export HCCL_SOCKET_IFNAME=lo
export PYTORCH_NPU_ALLOC_CONF=expandable_segments:True
export SGLANG_ENABLE_OVERLAP_PLAN_STREAM=1
export SGLANG_ENABLE_SPEC_V2=1
export SGLANG_PREFILL_DELAYER_MAX_DELAY_PASSES=20
export SGLANG_SCHEDULER_DECREASE_PREFILL_IDLE=1
export SGLANG_SET_CPU_AFFINITY=1
export STREAMS_PER_DEVICE=32

python3 -m sglang.launch_server \
    --model-path /mnt/weights/Qwen3.8-27B \
    --host 127.0.0.1 --port 6688 \
    --tp-size 4 \
    --nnodes 1 \
    --attention-backend ascend \
    --device npu \
    --chunked-prefill-size 16384 \
    --max-prefill-tokens 16384 \
    --trust-remote-code \
    --max-running-requests 16 \
    --mem-fraction-static 0.85 \
    --cuda-graph-bs-decode 1 2 4 8 12 16 \
    --dtype bfloat16 \
    --mamba-ssm-dtype bfloat16 \
    --speculative-algorithm NEXTN \
    --speculative-num-steps 3 \
    --speculative-eagle-topk 1 \
    --speculative-num-draft-tokens 4 \
    --reasoning-parser qwen3 \
    --mamba-radix-cache-strategy extra_buffer \
    --max-mamba-cache-size 40
```

**参数调整说明**（基线为 Qwen3.6-27B 部署教程的 BF16 配置：`--tp-size 4 --dp-size 2 --enable-dp-attention --chunked-prefill-size -1 --max-prefill-tokens 16384 --mem-fraction-static 0.85 --max-running-requests 64`）：

| 调整 | 原因 / 效果 |
|---|---|
| 新增 `--max-mamba-cache-size 40` | 不加时 `max_total_num_tokens=45184`，装不下一条 128K 请求，输出被截断为 1 token；加上后为 **585344** |
| 去掉 DP attention（`--dp-size 2 --enable-dp-attention`） | 32GB 卡上 KV 空间被分成两份，128K 场景下不够用 |
| `--chunked-prefill-size -1` → `16384` | 不分块时，128K 预填充在 warmup 阶段导致服务进程崩溃（32GB 卡上的显存峰值过高） |
| 新增 `--mamba-radix-cache-strategy extra_buffer` | 参考 Qwen3.6-27B 64k+90% prefix 最佳实践，让混合模型可以使用前缀缓存 |
| `--max-running-requests 64` → `16`，图档位 `1 2 4 8 12 16` | 与实际并发对齐 |
| 新增 `SGLANG_SCHEDULER_DECREASE_PREFILL_IDLE=1`、`SGLANG_PREFILL_DELAYER_MAX_DELAY_PASSES=20` | 取自 Qwen3.6-27B 128k 最佳实践配置。并发 8 时，TPOT 从 66.8ms 降到 46.9ms（-30%），吞吐从 91.6 升到 122.8 tok/s（+34%） |

#### 3. 性能测试

测试命令（128K 输入，其中 90% 为共享前缀，1K 输出）：

```bash
python3 -m sglang.benchmark.serving \
    --dataset-name generated-shared-prefix \
    --backend sglang \
    --host 127.0.0.1 --port 6688 \
    --gsp-num-groups 1 \
    --gsp-prompts-per-group 32 \
    --gsp-system-prompt-len 112300 \
    --gsp-question-len 12480 \
    --gsp-output-len 1000 \
    --max-concurrency 8 \
    --num-prompts 32 \
    --request-rate inf
```

### 对比总结

| 指标（并发 8，TPOT ≤ 50ms） | Qwen3.8-27B (BF16) | Qwen3.8-27B-w8a8 | 变化 |
|---|---|---|---|
| GSM8K 精度（200 题） | 99% | 98% | -1 个百分点 |
| Mean TPOT | 46.93 ms | 45.22 ms | -3.6% |
| 输出吞吐 | 122.76 tok/s | 131.65 tok/s | **+7.2%** |
| Mean TTFT | 15.30 s | 13.54 s | **-11.5%** |
| 投机接受长度 | 3.36 | 3.55 | +5.7% |

结论：

1. **W8A8 精度基本无损**（99% → 98%，200 题中只差 1 题），性能小幅提升：吞吐 +7%，首字延迟 -12%。
2. **在 128K 长上下文场景下，量化的收益有限。** 瓶颈主要在注意力计算和长预填充对解码的打断上，从 ITL 的分布可以看出来：中位数约 20ms，但 P99 超过 1.1s，最大值超过 12s。量化主要加速线性层，对这部分帮助不大。
3. 本次调优中**收益最大的是调度参数**：加入两个预填充调度环境变量后，同样并发 8，TPOT 从超标的 66.8ms 降到 46.9ms，吞吐提升 34%。
4. **在 32GB 的 A2 卡上，混合模型（Mamba/GDN + Attention）跑 128K 时，必须限制 `--max-mamba-cache-size`，并且开启分块预填充**，否则输出会被截断或服务崩溃。

## 四、问题与改进建议

### 发现的问题

1. **混合模型的 KV 容量不足时，输出被静默截断。** 32GB 卡上使用教程配置时，`max_total_num_tokens=45184`，128K 请求的 `max_new_tokens` 被裁成约 1。服务端和 bench 都不报错，bench 显示"成功"，TPOT 为 0。
2. **`--chunked-prefill-size -1`（教程默认）在 A2 32GB 上跑 128K 会崩溃。** warmup 请求进行中，服务进程退出，客户端只看到 `TransferEncodingError`。
3. **最佳实践缺少 A2 和 128K+prefix cache 场景**，调度环境变量也缺少说明，而它们对长上下文的 TPOT 影响很大（-30%）。
4. **generated-shared-prefix 数据集的实际长度比参数大约 2.6%**（分词重编码）。按"128K"直接设置参数，实际约为 131K。
5. 任务书中容器创建命令的挂载路径写成了 `/etc/ascend_install_info`，正确的是 `/etc/ascend_install.info`。

### 改进建议

1. 当 `input_len + max_new_tokens > max_total_num_tokens` 时，服务端应打印 warning，或者直接拒绝请求；bench 在 `Total generated tokens` 少于期望值时也应给出警告。
2. 在 Qwen3.6/3.8 的部署文档中，补充 A2（32GB）上 128K 长上下文的推荐配置：`--max-mamba-cache-size`、`--chunked-prefill-size 16384`、关闭 DP attention。
3. 在参数调优文档中，补充 `SGLANG_SCHEDULER_DECREASE_PREFILL_IDLE` 和 `SGLANG_PREFILL_DELAYER_MAX_DELAY_PASSES` 的说明，并附上本次的实测收益。
4. 在性能测试文档中，补充"X% prefix cache"用例的构造方法，并提示分词膨胀的问题。
5. 修正任务书中的 `ascend_install.info` 路径。
