# results/

Outputs of one benchmark run. Generated by `bench/run_matrix.sh`, summarised by `bench/summarize.py`.

```text
results/
├── <cell>.jsonl          SGLang bench_serving output (one JSON object per run; with --output-details it
│                         also carries the per-request arrays ttfts / itls / input_lens / output_lens)
├── <cell>.meta.json      wall time, exact command, hardware tuple -> the provenance of the number
├── summary.json          all cells merged (what summarize.py read)
├── server.log            server stdout/stderr
├── logs/
│   ├── server.pid
│   ├── launch-command.txt  exact command + env overrides used for this run
│   ├── bench-<cell>.log
│   └── server-metrics.log  /metrics samples (prefix-cache hit rate, running/waiting requests)
├── telemetry/
│   ├── telemetry-*.csv     npu-smi samples during the run
│   └── snapshot-*.txt      one-off hardware snapshots
└── smoke-*.txt             smoke-test evidence (health, model info, chat reply, npu-smi)
```

## What to commit to git

Commit: `*.jsonl`, `*.meta.json`, `summary.json`, `logs/launch-command.txt`, `smoke-*.txt`,
`telemetry/snapshot-*.txt`, and **at most one** representative `server.log` (or just its first 200 lines).
Do not commit: multi-hundred-MB telemetry CSVs, repeated server logs, checkpoints.

Rule: a number without its `meta.json` is not a result, it is an anecdote.
